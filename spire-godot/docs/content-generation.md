# 内容生成规则

2026-09-07 补充：[可直接接入的内容包](../content/README.md) 已实现五类声明式模板。文件校验后合入下述原注册表与真实来源，不建立第二套规则。以下内部架构说明继续适用于需要新机制的开发。

核对日期：2026-09-07。适用目录：`spire-godot/`，独立 Godot Demo。

本文件说明**现在如何生成、扩展时必须遵守什么、哪些能力尚未实现**。可复制的设计表与数据例子见[内容模板](content-templates.md)；执行接口见[内容扩展接口](content-extension.md)。完整数值与结构规则仍查[游戏设计](game-design.md)、[装备设计](equipment-design.md)。用户最新明确决定优先；文档与代码不一致时应报告差异，不能悄悄改规则来迁就旧代码。

## 1. 共用原则与工作入口

1. 先选择内容家族，再填写模板。普通拘束具、复合拘束具、链接、特殊部位装备、随身道具、遗物分别有自己的定义与工厂；JSON 内容包按五种 kind 分别校验，不存在任意物品都能通吃的结构。
2. 区分稳定的**类型 ID**与本局的**实例 ID**。数据表保存类型，工厂分配实例；目标、来源、组件、锁与连接使用真实实例引用，不能用中文名称寻找对象。
3. 先查询合法选项，再冻结随机结果，提交时复核当前资格，最后整体结算。界面只读 `get_view()` 并调用 `Game.dispatch(candidate_id, expected_version)`；下文带下划线的工厂是内部接口，不能接成绕过候选的按钮。
4. 一次选择的费用、安装、奖励、编号与日志必须一起成功，失败全部回滚。预览、悬停、切换面板不能抽随机数、安装装备或推进回合。
5. 定义、活动池、实例、显示是四层。登记定义不代表完成生成；但某些入口会枚举整个定义表，新增类型也可能自动进入这些入口。每次都检查下表，不能假设存在统一的 `enabled` 开关。
6. 新效果必须接入真实规则、存档校验、状态／结果投影和测试；文案与美术不能充当规则实现。Demo 不为旧规则复制第二套逻辑，也不默认补旧图或旧装备的迁移层。

| 内容 | 定义 | 正式生成／取得入口 | 内部执行入口 |
|---|---|---|---|
| 普通拘束具 | `data/equipment.gd`：`TEMPLATES`、`MATERIALS` | 敌人模板池、警卫合法方案、事件配方、监狱 | `Game._installation_reason` / `_install_template` |
| 复合拘束具 | `data/composites.gd`：`spec`、`GENERATION` | 警卫／事件筛选、监狱指定组合 | `_assembly_reason` / `_install_assembly` |
| 链接绳 | `data/links.gd`，材料方法复用 equipment | 含绳索／皮带类的普通池、显式link_rope池及明确练习配置 | `_install_link`，端点清理 |
| 普通单件拘束具 | `data/equipment.gd`：`TEMPLATES`、`WEAR_TEXTS` | 敌人、事件、监狱与练习共用普通安装来源 | `Application`、普通装备工厂与事件部位佩戴正文 |
| 特殊部位装备 | `data/special_equipment.gd`：`TYPES`（含可复用`wear_text`）、`DESIGNS` | 内置练习；外部内容包的附带地图事件／显式 `special_install` 效果 | `Game._install_special`、既有解除与触发管线 |
| 随身／已安装道具 | `data/field_tools.gd`：`TYPES` | 商店、休息服务、事件、监狱发现、练习各自登记 | `_gain_tool`、原道具候选与执行 |
| 遗物 | `data/relics.gd`：`TYPES`、`REWARDS` | 初始配置、商店、宝箱、事件 | 既有领取与 `core/relic_effects.gd` |
| 敌人／遭遇 | `data/enemies.gd`：`TYPES` / `ENCOUNTERS`；`data/first_floor_enemy_pools.gd`：`POOLS` | 塔路冻结遭遇、精英／塔顶配置、练习 | `_spawn_enemies`、`core/enemy_plans.gd`、`core/guard.gd` |
| 事件 | `data/room_events.gd`：`TYPES`、`pool()` | 抵达事件房时，从本局尚未出现的正式事件中抽取 | `core/room_events.gd` |

### 随机与结果保存

| 内容 | 随机来源 | 何时决定、如何保留 |
|---|---|---|
| 塔路连线、房型 | `Tower.generate(run_seed)` 的局部带种子随机器 | 生成整张塔路时写入房间；不预选事件 |
| 事件 ID | `event` | 抵达时排除本局`event_seen`后抽取，写入房间并立即记录；放弃事件也不退回池中 |
| 普通房间的弱／强遭遇备选 | `encounter` 随机域 | 生成塔路备选；首次进入按已完成普通战斗数选定，写入 `encounter_selected` |
| 敌人计划／施加选择、材料版本 | `enemy` / `equipment` | 预告保存池与规格要求，出手时选择实际装备；打断只延后，查询与读档不抽随机 |
| 事件施加方案、有效钥匙、候选遗物 | `event` | 进入事件时保存于 `room_event` |
| 事件三选一奖励牌 | `reward` | **选择并成功支付代价后**生成，随后保存；不是进房即抽好 |
| 战后／休息奖励牌 | `reward` | 对应奖励阶段生成后保存 |
| 商店／宝箱 | 种子、塔路代数、房间 ID 派生的局部随机器 | 首次进入生成 `stock`，领取后标记 `taken`；重开面板不补货 |
| 战斗距墙、施法、牢房位置、探索摔倒、牌堆 | `position` / `magic` / `explore` / `fall` / `deck` | 沿各自既有调用点及存档计数 |

完整随机域清单与各域盐值只维护在`data/balance.gd::RNG_SALTS`。Game初始化按该表创建全部零计数，Snapshot按同表要求完整且无额外域，每个计数必须为非负整数；返塔按现有域归零。不要借显示代码或全局`rand*`增加不可重放的抽取。新增域须登记此表并覆盖实际执行与保存恢复；若破坏存档结构，提升Snapshot.REVISION，不迁移或补填旧档。

事件按稳定ID在每局内最多出现一次。存档／读档保留记录和已选事件；出狱返塔、出口继续游玩均开始新局并清空记录。池耗尽时成为可通过的空房间，不发奖励。练习指定事件不占用正式局记录。

目前没有通用权重、稀有度、幕数门槛或保底配置引擎。事件去重为统一规则，不需要额外`unique`配置；其他需求不能只添加`weight/rarity/act`就声称生效。

## 2. 普通拘束具

2026-09-07新增皮革眼罩 `eye_leather`：只允许中／高级，复用皮革材料、16／24耐久、眼罩滑脱与视觉限制、徒手及锁接口，不增加效果。归入漂浮皮带的最终附着池，最低中级，因此初级施加不会抽到；警卫通用选装沿原注册表枚举。练习提供中／高级两项，胶带眼罩归入胶带池。

2026-09-07口球更新：`mouth_band`沿用原安装接口，显示名替换为普通口球／马具口球／普通假阳具口球／马具假阳具口球，对应等级1／2／2／3。中级variant 0／1区分两种组合，既有equipment随机域冻结并保存，不增加随机域。马具与口球合为一件，不再从复合方案追加head/harness。练习提供四种组合；浮游怪、警卫及高安全追加沿原等级和口部安装来源。卡牌、费用、施法、锁与材料数值不新增规则。

### 2.1 等级、紧度与方法

| 项目 | 当前规则 |
|---|---|
| 装备等级 `grade` | 1 初级、2 中级、3 高级；普通最大耐久分别为 10、16、24 |
| 材料版本 `variant` | 对应材料在该等级下的数组下标；不是装备实例编号 |
| 紧度 | 从当前耐久／最大耐久计算。一档比例 ≤40%，二档 ≤80%，其余三档；归零进入移除／结构清理 |
| 生成紧度 `tier` | 一／二／三档初始耐久分别为最大值的 40%／80%／100% |
| 加固一档 | 一档提升至 80%，二档提升至 100%；不能给满耐久目标继续加固 |
| 模板方法 | `strain/slip/manual/lock` 分别声明挣扎、滑脱、徒手、上锁能力；声明为真仍需经过实时资格检查 |
| 结构性禁止 | 不能滑脱、外层遮挡、锁、封闭区等继续生效，不能因“降低紧度”一概开放 |

伤害统一走 `Game.escape_preview` 和原损伤执行。它综合紧度、锁、同层堆叠、属性、环境和辅助；不要在新模板、敌人或 UI 复制公式。普通滑脱的三档免疫和魔法滑脱的区别同样复用原方法。

口部装备会影响以嘴为施法部位的魔法：等级乘区为 0.5／0.25／0，紧度乘区为 1.5／1／0.5。最终成功率沿统一施法查询量化到 0.01%；不能恢复“口部被占用就禁止全部魔法”。手势条件另外检查。免费准备不掷成功率；付费失败仍扣本次实际费用与牌，不产生效果。

### 2.2 部位、精准位置与容量

身体显示入口不是安装槽。手部入口合并手掌／手指，足部入口合并脚掌／脚趾；内部仍保留分别的能力判定。颈部显示脖颈／肩部，当前普通自动安装槽中**没有** neck／shoulder；现有肩带在肩部显示不等于任意普通绳索可以安装在那里。

| 规则槽 | 精准位置／说明 |
|---|---|
| `eyes` / `mouth` | 眼部／口部，由专用模板处理 |
| `upper_arm` | `upper_arm_top` 大臂上侧、`above_elbow` 手肘上方 |
| `forearm` | `below_elbow` 手肘下方、`mid_forearm` 小臂中间 |
| `wrist` | 手腕 |
| `palm` / `fingers` | 掌／指各有 `_left`、`_right` 精准点；是否成对或单侧由真实结构决定 |
| `thigh` | `thigh_root` 大腿根、`mid_thigh` 大腿中部、`above_knee` 膝盖上方 |
| `calf` | `below_knee` 膝盖下方、`mid_calf` 小腿中间 |
| `ankle` / `foot` / `toes` | 脚踝／脚掌／脚趾 |

容量按真实占位点检查：掌、指、脚掌、脚趾默认 2，口部 1，其他普通槽默认 3。普通大腿／小腿单件只占实际安装的一个分段，不能因为 UI 分组而盖满整段腿。指定精准点必须保持；未指定时工厂选占用最少的合法分段，平手按身体顺序。复合结构按真实覆盖另行核查。

普通大部位池 `LARGE_SLOTS` 为大臂、小臂、手腕、手掌、大腿、小腿、脚踝、脚掌；小部位池 `SMALL_SLOTS` 为掌、指、脚掌、脚趾。绳、细绳、皮带、细皮带分别使用对应池；胶带／扎带使用普通肢体槽。眼部与口部不能借肢体模板自动覆盖。

### 2.3 安装顺序、层级与来源

`EquipmentOffers.ordinary(g, grade, free, templates)` 查询合法方案。空 `templates` 会枚举所有有合法槽的普通模板：**新增普通定义可能立即被警卫通用选装选到**，即使没加入浮游怪的专用池。草稿应保留在文档；若要“注册但暂停生成”，先设计明确的来源过滤。

2026-09-08统一为三档：空手腕第一；空口部／手指第二；所有其他合法位置、已有装备追加和链接类第三。后台rank分别为3／2／1（数值越大越优先）。先按来源模板、等级和结构枚举，再从最高档合法方案中随机选择；不改变界面排序。普通池含rope、cord、belt、fine_belt、eye_leather或其base_template派生款时自动加入合法链接绳；也可显式声明link_rope。不免费补装两端，明确要求上锁时排除不能上锁的链接，具体部位要求必须同时满足两端。

安装工厂统一检查模板、等级、可上锁性、容量、封闭区与层级。普通新件进入合法外层；复合结构冲突不能用任意 `layer` 或直接追加数组绕过。敌人、事件、监狱均写清 `source`，方便执行时寻找自身施加的目标与日志归属。

2026-09-07最新修正：躯干固定改为“躯干固缚”附加状态。大臂／小臂／手腕普通单件施加或加固到三档时随机产生连接式或一体式；降档不消失，二档再加固至三档也刷新。连接式有独立耐久，挣扎不受堆叠影响、滑脱受影响；一体式无独立耐久，两种方法均受堆叠影响。大臂令手不可触及大腿，小臂／手腕另禁占位位置3。仅最外层生效，同层可追加，禁止普通外层覆盖；成功施加重合复合装备前取消状态，失败保留。原装备移除时级联解除。详见docs/equipment-design.md第7.1节。

## 3. 复合拘束具与链接

复合物不是“多个普通物品碰巧同名”。`Composites.spec(kind, variant, straps)` 定义一个根与真实组件；组件各自保存耐久、锁、覆盖、接触、层级与归属，根没有另一条重复扣减的总耐久。

- 现有家族：`glove` 单手套、`leg` 单腿套、`jacket` 拘束衣、`wrap` 单侧包裹、`head` 头部马具。普通生成组合由 `GENERATION` 显式列出；头部马具仅在存在可依附的真实口部固定带时追加合法方案。
- 单手套分 short／long 和 straight／cross 肩带；长型关闭掌／指，肩带先处理后的套体脱除复用原结构判断。
- 单腿套分 upper／lower／ankle／toes。外带声明精确固定点并独立计耐久；套体移除后允许留下真实外带，不能连同整个根不加判断地删除。
- 单侧包裹有 left／right；不能为了计算方便封住另一只手。`coverage`、`contact`、`points`、`side` 与 `independent` 含义不同，显示位置也不反向修改接触范围。
- 新复合结构即使复用组件模板，也必须补齐结构解除、残留、封闭、容量、关联清理和存档规则；仅新增一条 `GENERATION` 不能实现新家族。
- 链接候选统一读取 `EquipmentOffers.links`：区域内纵向子部位可任意相连，跨区域只取相邻边界，股绳仅接手腕／大腿根。每对物理装备最多一条；每件每方向取区域内剩余子部位数、最低1作为额度。复合按真实组件共享额度，不把整件覆盖视作多件。`contact_points`随两端保存并复核；不可伪造位置或迁回区域级模糊连接。
- 链接必须由 `_install_link` 连接两个仍存在且合法的物理目标，使用一条共享链接耐久；两处显示不能变成两条绳。链接不冒充普通部位占位。解除链接保留两端装备；端部装备被真正移除时按共用清理规则删除失去依附的链接。
- 五级终局使用既定高安全装备组合与合法填充流程；旧 `security/terminal` 固定架不加入新生成。不要把其 1000 耐久或零伤害倍率作为普通新品模板。

## 4. 性玩具装备（独立家族）

本节使用已具名的身体位置、固定品质与耐久方案，不再使用编号占位名称。

| 区域 | 子位置 | 每个子位置容量 |
|---|---|---|
| 乳头 | `special_1_a` | 2 |
| 肉棒：柱身／龟头／冠沟／马眼 | `special_2_a/b/c/d` | 2／2／2／1 |
| 双穴：小穴／后庭 | `special_3_a/b` | 1／1 |

同槽多件分别选择、损伤与移除。不能用普通拘束具填这些槽，也不能把其数量计入普通双臂／双腿受限等级或普通道具容量。裆部股绳同时显示在小穴和后庭，但容量消耗为0、同族最多一个，刺激只落在小穴。复合榨精杯原子占用全部声明位置。

### 4.1 定义与生成

`TYPES[type]` 管名称、家族、触发数值、刺激位置、材质说明与正文：`name/family/energy_gain/turn_gain/duration/stimulates/material_text/detail`。

`DESIGNS[type]` 管固定规格：`grade/maximum/ratio/slots/methods/tools/environments/damage_factor/capacity_cost`。两表必须同 ID 成对登记。品质和最大耐久按作者设定固定，初始耐久为 `maximum × ratio`；不套用普通材料随机表。当前等级最大耐久为10／16／24，初始比例均80%。

敌人与事件的通用性玩具随机名单集中在`SpecialEquipment.RANDOM_POOLS`。飞机杯家族不进入通用名单；外置震动棒只登记中级及以上随机款。监狱使用独立的`SpecialEquipment.prison_pool`，保留各等级股绳，并从警戒度3级起开放同等级飞机杯。明确指定type的事件和练习也不受通用池限制。

`Game._install_special` 检查类型、允许子槽与该槽容量后才分配编号并安装。实例由工厂建立，不能手拼；当前 material 等字段用于已有装备查询适配，不是已开放的特殊材料／随机上锁配置。

当前具名成品已进入注册表、独立练习、敌人通用随机池和监狱独立池。内容包可通过现有事件`special_install`安装已登记类型；若让新敌人或商店正式施加，仍需补所属操作、合法目标、预告、结果、存档和测试。不要把`special`普通适配模板的空`slots`填满来绕过工厂。

### 4.2 触发与到期

| 配置关系 | 触发与到期 |
|---|---|
| `energy_gain>0` | 每次行动实际支付正能量时触发一次，不按能量点数重复计算 |
| `turn_gain>0, duration>0` | 玩家回合开始触发一次并消耗一回合电量；电量耗尽后停止全部自动刺激，装备保留 |
| `duration=0` | 无电量倒计时，按声明的触发方式持续生效 |

零能量动作与多段牌续段不额外触发支付被动；返还不会撤销已发生的支付触发。贴墙起身／室内移动如实际支付能量则触发一次，但不会因为按钮执行自动进入下一回合。触发、损伤和到期都走正式状态，不在 UI 定时器结算。

每个可玩性玩具家族还必须在`STIMULATION_TEXTS`提供当前佩戴时的具体刺激正文，不能拿安装动作或`detail`泛称代替。装备详情与“装备刺激”状态均从当前实例生成公式：`基础刺激 × 部位倍率 × 可选锁内震动系数 × 当前来源倍率＝实际快感`；电量耗尽和限时效果结束显示0，不能继续展示过期收益。状态短文案不包含解除牌名、环境资格或操作教程，多部位复合根按物理ID去重；实际解除入口继续读取正式候选。

### 4.3 解除、接触与环境

玩家 `action_targets` 包含特殊根；普通敌人 `equipment_targets` 不因此获得新的施加类别。普通挣扎／滑脱继续使用真实紧度、锁／堆叠规则与手部辅助；每只手手指自由时基础＋1，手掌不能使用时减半为＋0.5，两手分别相加，不是最终伤害直接加值。

`methods`白名单使用已有`strain/slip/magic_slip/lower/focus/manual`。普通挣扎／滑脱／专注在没有任何一只手能触及目标时，需要真实可借用环境；魔法降档／魔法滑脱按施法条件，不统一套手部门槛。挂钩和尖锐处是现有卡牌的环境条件，不为性玩具生成独立的直接拆除候选。

| 已支持环境／安装方式 | 额外实际条件 |
|---|---|
| `wall` | 当前贴墙且房间确有墙 |
| `sharp` | 当前贴墙、确有仍有次数的兼容已安装工具，并能接触该安装处 |
| `hook` | 当前贴墙、休息阶段、挂钩剩余次数>0，并且装备位置能接触挂钩高度 |

手部可达统一查`core/contact.gd`、`core/hand_assist.gd`：双臂自由时全姿态可触及全部性玩具位置；手腕自由时额外触及手肘上方、乳头、肉棒与双穴区域；正常大腿范围包含双穴区域。操作是否精细、同手能否自助、外层遮挡仍另外复核，不能仅按“手部入口0件”判断。小穴／后庭无线跳蛋另要求双臂、双腕、双手掌和手指全部自由后一次直接取出。

## 5. 道具、遗物与物品来源

### 5.1 道具

`FieldTools.TYPES` 字段为 `name/uses/damage/materials`，可选 `operation`、`mouth_install` 和 `trigger_damage_types`；operation省略时是 `cut`。现有 operation 为 `cut/unlock/escape`，不能随意填新动词。切割沿固定耐久损伤、材料白名单、真实触及／外层检查；头颈部不能因材质兼容就获得普通切割路线。

物品实例保留 type、剩余 uses、mount。`carry/foot_wall/hand_wall/high_wall` 共用同一件物品及次数；安装耗1能量，不消耗使用次数。已安装物品必须始终可重新打开交互，离房前未取回则不随身带走。挂钩是休息环境次数，不是另一个无限使用道具。

随身道具先展示正式候选中的合法位置，再选择目标。已安装切割工具仅由卡牌的实际 `damage_type` 匹配 `trigger_damage_types` 触发；魔法滑脱的伤害类别为 `slip`，不以牌名或是否魔法作白名单。每张牌每工具最多一次，重合时择最强可用工具，触发才扣次数；原牌已解除目标时不耗工具。完整规则见[主规则6.2A](game-design.md)。

稀有遗物触手朋友提供unrestricted_items=1，取消道具身体、姿势和触及限制。带trigger_damage_types的随身工具由Tools.is_fixed视为固定，全身可达，仍走同一出牌触发／扣次；真实mount与容量不改，不把魔瓶或卷轴归入固定工具。材料、外层、方法与目标资格保留；Consumables只跳过身体条件，口部减效仍统一读取potion_amount。

随身基础容量3，遗物可加容量；双臂受限≥3或手指全部不能活动时减1，双腿受限≥3再减1。使用正式容量查询，别在奖励与商店各写公式：商店满容量拒绝购买；事件等已取得奖励后超容量进入整理，不悄悄销毁奖励。

新增道具要逐一选择来源：商店 `data/room_services.gd` 的 `TOOLS+PRICES`，事件效果／奖励，休息服务候选，`core/prison.gd` 活动发现池，或练习配置。折返符有定义和使用机制，**暂不进入任何正式生成池**。

### 5.2 遗物与卡牌奖励

2026-09-10：新增通用`turn_energy_step`，每累计指定数量玩家回合增加1能量，按遗物ID独立保存在relic_counters且跨战斗保留。开心小fa使用3并登记罕见一般奖励。统一回合入口消费，统一counter投影显示右下角数字；其他不累计的hook不额外生成计数。魔力耳坠的已有耗魔余数也接入该显示投影，不改变其场次清零规则。

遗物 `TYPES` 需要 `name/detail/rarity/modifiers`；当前已消费的数值 hook 包括 `battle_mana/capacity/preparation_turns/opening_draw/turn_draw`等。`turn_draw`由统一玩家回合入口读取，覆盖战斗、牢房、休息和整备。新的 hook 必须有真实读取／触发代码。断缚护腕等有额外事件条件的遗物由 `RelicEffects` 处理，不能只写一个看似合理的 modifiers 键。

随机遗物来自 `REWARDS` 并排除已持有；初始余烬护符与明确指定事件来源的遗物可只登记`TYPES`而不进入`REWARDS`。当前无每个敌人的独立掉落表，战后使用共用奖励流程；不要凭敌人模板的 `loot` 字段发物品。

卡牌定义与池分别维护 `data/card_rules.gd` 的 `SPECS/COMMON/ADVANCED/REWARDS`，名称、说明和特性查 `data/balance.gd`。奖励 `reward_offer(pool)` 在同次选项内不重复、跨次允许相同牌，最终统一 `_gain_card`。保持现有三选一池足够大及快照约束；新增空池／不足三张时的行为需要连同存档与 UI 实现，不能只缩短池数组。

### 5.3 商店与宝箱

奥利哈基米以罕见一般遗物olihakimi进入REWARDS，unspent_turn_mana=8共用回合结束的魔力恢复hook。是否消耗魔力只读本回合正式付款事实，不用魔力净变化或耳坠余数判断；零费和魔瓶转移不计，付费失败同样计入。

普通遗物传单以shop_flask_mana=20进入一般遗物池。每间商店首次初始化时给魔瓶补充20魔力，共用遗物资源反馈；重开商品界面不触发，在店内取得不补发。魔瓶没有容量上限，不消耗手动存入次数。

商店货币是魔力：普通牌15、罕见牌25、稀有牌40；普通遗物45、罕见遗物65、稀有遗物90，特殊补位遗物45、小石片10、锯条15、开锁针18、删牌25；当前价格统一在 `data/room_services.gd`。支付不是施法，不掷成功率，不能使用临时魔力，不触发施法返还。

每店固定2张普通、2张罕见、1张稀有卡牌，各品质内不放回抽取，不使用卡牌稀有率修正；4种不同道具从小石片、锯条、开锁针及全部6种药剂／卷轴中抽取，新增药剂与卷轴暂定各15魔力；3个一般遗物货位沿原稀有度分布，排除已持有／已展示的一般遗物，抽中空品质池时发放滚木。货位与道具池统一维护在data/room_services；查看、付款来源切换或重开面板均不补货。宝箱按原品质概率提供一件遗物；该品质池耗尽时改给无效果的滚木，已持有滚木仍可领取并增加数量。每店保留一次删牌，购买与删牌标记随房间记录。

## 6. 敌人与遭遇生成

### 6.1 三层数据与选池

`TYPES[type]` 定义个体，`ENCOUNTERS[id].members` 组合个体，`data/first_floor_enemy_pools.gd:POOLS.weak/strong` 决定第一幕普通房间的遭遇；`enemy_library.gd:CLASSIFICATIONS` 独立分类个体。新增怪物须完成三层引用，不把敌人类型直接塞入遭遇池。

当前弱池从已登记单体中按装备条件过滤，再逐个抽取能够补齐剩余预算的成员，总强度恰好2，允许同种重复。前三次普通战斗使用弱池，之后使用总强度4的登记组合，并排除上次强怪组合。现有组合为一团X＋强度1弱怪、四只强度1弱怪、两只杂乱拘束具、单只魔导拘束盒。精英为 `guard_solo` 或 `heap_family`，塔顶固定为 `six_bind_solo`。组合练习不自动进入随机池，完整名单见 [第一幕怪物库与出场池](first-floor-enemy-library.md)。

`strength` 是模板后台正整数，当前弱怪允许1或2；内容包须显式填写。它参与弱怪总强度2的组队预算，不缩放当前其他数值，不写入玩家视图，不显示在战斗、图鉴或教程。`members` 项为 `{type, grade}`，可附 `pressure`；grade 不是生命倍率。常规材质怪的普通／最终安装分别固定初级／中级，紧度均为2；口球当前成员固定初级。不要依靠修改成员grade升级常规材质怪。

### 6.2 已实现行为

| behavior | 行动骨架 | 附加定义 |
|---|---|---|
| `restraint` | 初级2档随机施加→加固同类，优先自身来源，生成意图时无目标才改选既有施加→准备→中级3档附着并离场 | `install_pool/final_pool`；真实子位置与最低品质过滤 |
| `attachment` | 准备两次→固定部位附着并离场 | `attachment_slot/attachment_pool`；当前为中级3档口球，口部容量1 |
| `dispenser` | 准备→佩戴→停顿，循环不离场 | `special_pool` 显式白名单，复用特殊装备工厂 |
| `lock` | 预告上锁→上锁，循环不离场，仅已有装备 | 共用上锁资格、预告与目标复核 |
| `guard` | 既有警卫序列、附加行动、收押准备与执行 | `core/guard.gd`，不是任意动作数组解释器 |

`hp` 是模板生命，`order` 越小越早。当前绳索10、皮带20、胶带30、扎带35、锁36、口球40、玩具箱45、警卫50。相同类型的实例ID各自独立，不按中文名识别或选择目标。`visual` 与行为独立：现有图片和简易绘制外形由统一arena显示。

### 6.3 目标复核、冻结与反馈

公开意图在执行时由 `EnemyPlans.resolve` 复核。加固预告不指定目标；生成时没有合法目标才从该敌人的既有施加意图中选择。已预告的加固在出手时没有合法目标便空过，批量缺额也不补施加。实际目标共用`EnemyPlans.targets`的来源与方法资格，警卫仍使用其声明的通用范围。

普通、复合和特殊施加共用Application：出手时从声明池选择合法位置与具体规格，替换必须有显式权限。口球来源声明口部优先及自己的模板池；玩具箱从special_pool出手选择，没有候选仍推进原步骤。打断延期当前步骤，预览不消耗随机；存档保存真实敌人实例与公开意图，不在恢复时补抽装备。事件仍按其阶段冻结时机保存具体请求，执行时不重抽。

新增行为或意图须同步计划、复核、执行器、`Snapshot.intent`、`intent_view`、行动文案及反馈名称。眼部受限隐藏未来意图和准备细节，实际造成的变化仍写结果与日志。动画读取正式敌方行动事件，不能在动画结束时再次修改装备。

## 7. 事件生成与结算

### 7.1 作者原则与当前入口

事件要让收益与代价同时成立：例如接受额外装备换牌、处理已有装备换更高奖励、接受公开风险参加赌局。入场说明应预告具体代价和概率；不能把所有选择写成无风险领取，也不能靠漏写失败效果制造风险。正文先用简短中性文本，具体叙事由独立文案包补充。

**正式抵达事件房时，从 `EventData.pool()` 排除本局已出现事件后均匀抽取ID。** `pool:false`可保留练习定义但排除正常塔路。同局不重复；出狱返塔或出口继续时清空记录，存档／读档保留。池耗尽为空房间。不提供额外权重、幕数门槛或单独的去重开关，草稿不要提前写入正式池。

普通流程为：`进入并冻结方案 → 选择并原子支付／施加 → 钥匙或选牌或结果 → 容量整理 → 地图`。多阶段流程为：`进入阶段并冻结本阶段全部选项 → 选择并原子提交 → 后续阶段／结果 → cleanup_effects → 容量整理 → 地图`。两者都不触发普通战后恢复，也不给额外整备回合。

### 7.2 数据与配方

事件条目需要`name/intro/start_node/nodes`；每个节点声明`allow_refuse/unavailable/relic_gate/random_freeze/outcome_draw/frozen_form/empty_node`并填写`choices`，每个选择需唯一`id/label/reward`，配`recipe`、`effects`或`outcomes`。节点`allow_refuse`无默认：为真时自动追加支付至多10魔力的付费离开选项，为假时不会生成默认离开；作者仍可用无奖励空`effects`提供免费离开。选项可用`hide_when_unavailable`要求完整效果当前无法成立时直接隐藏，也可使用通用`selector`。选项还可声明通用`encounter{id,requires_defeat,victory_effects,victory_report,result_status}`，进入已登记遭遇并在胜利后直接回到事件结果页；它不产生普通战利品或整备，`reward`必须为`none`。`item_rewards:[{id,pool}]`可从1—6个道具池各冻结一件，通过共用战利品界面逐件领取或放弃；容量已满时就地禁止，不进入整理或整备。定义级`cleanup_effects`可声明`restore_held`收尾；单节点定义的节点`id`固定为`choice`，多节点定义按`start_node`进入第一个节点。完整字段见内容包说明及两个`event`模板。

| recipe | 当前固定行为 |
|---|---|
| `free_basic` | 从合法空闲部位中按优先选择绳／皮带，初级一档 |
| `tighten_or_medium` | 有未满耐久的真实组件／单件时随机加固一档；否则合法施加中级二档绳／皮带 |
| `locked_assembly` | 合法单手套／单腿套／拘束衣，中级、各组件二档，锁住预先选择并公开的可锁组件 |
| `wager` | 初级一档布带眼罩＋中级二档已锁皮带，保存 eyes／belt 引用，进入既有三钥匙玩法 |

无合法方案的配方不生成该选择。候选再于临时副本探测完整效果序列；提交仍复核。没有可抽遗物时，`relic/keys` 奖励的选择不生成。

奖励类型只有 `common/uncommon/rare/relic/keys/none`。普通／罕见／稀有卡牌奖励分别从对应稀有度生成3张候选，可跳过，已付代价不退；遗物在进房时选自未拥有池并固定。

### 7.3 效果白名单及尚未补齐的组合

| op | 当前执行字段 | 注意 |
|---|---|---|
| `install` | `template, slot, grade, tier, locked`，可有 `ref` | 目前事件执行器不传入精准 point／材料 variant／position，实际按工厂默认选择；仅写这些字段无效 |
| `assembly` | `family, variant, straps, part`；显示另需 `name, coverage, part_name` | 当前固定中级二档并上锁指定组件；不能只加 grade/tier 字段改变它 |
| `tighten` | `target` 或 `ref_target` | 加固现有装备到下一档上界，不是自由填写伤害或增量 |
| `unlock` | `target` 或 `ref_target` | 只解除锁，保留装备 |
| `pressure` | `amount`，可有`source` | 走统一压力／高潮与魔力损失流程 |
| `mana_loss` | `amount` | 当前日志按“付费离开、无奖励”撰写，不能原样用于付费购物事件 |
| `mana_gain` | `amount` | 恢复魔力但不超过角色当前上限；适合治疗、补给与交换事件 |
| `mana_restore_full` | 无 | 将角色当前魔力恢复至当前最大魔力；适合完整休息或大型补给 |
| `mana_max_loss` | `amount` | 永久降低最大魔力；若当前魔力超过新上限则同步压低，且不能令上限低于1 |
| `flask_mana_gain` | `amount` | 直接增加贴身魔瓶储量，不受角色魔力上限约束，也不占用每回合手动存入次数 |
| `card/tool/relic` | `type` | 必须已注册；遗物不能重复；道具取得后可能需要整理容量 |
| `remove_restraints` | `targets:$selected` | 配合`kind:restraint`且`count:1—4`的选择器；先复核全部冻结实例，再在同一事务内完全解除 |
| `tighten_to` | `target, tier` | 将冻结的真实目标收紧到2或3档；不能降低或重复收紧 |
| `hold_special` | `key, slots` | 暂存覆盖任一指定特殊部位且没有连接的既有性玩具 |
| `restore_held` | `key` | 从暂存记录原样归还；作者数据只放在顶层`cleanup_effects` |

普通与多阶段选项的`selector`都可用`count:1—4`冻结多个不同实例；拘束具选择器可用`include_special:false`排除性玩具，卡牌选择器可用`exclude_curses:true`排除诅咒。多阶段作者效果另支持`install_random{templates,count,grade,tier,locked,allow_links?}`和`tighten_random{count,to_tier,templates?}`。两者会在进入阶段时沿`event`随机域依次选取合法结果，立即展开成上述运行效果；数量范围1—4，同一批收紧不会重复选择已经达到目标档位的对象。`allow_links`默认开启；明确写成`false`时只保留普通单件，不会因绳索／皮带来源自动加入链接绳。选项的`outcomes`支持2—8个加权结果，每项含`weight/effects`并可覆盖`next/reward/report`；选项必须提供不泄露已冻结结果的`detail`。

状态条件写在选项上：规范拼写`conditions`（1—8条，每条`{kind, mode, reason, …}`）或兼容拼写`availability`，两者互斥；`kind`只取声明表里的种类。`mode`的`optional`使选项显示但禁用并给出`reason`，`hidden`使选项不生成（不进冻结选项与候选）。全部条目按 AND 判断，任一`hidden`命中即隐藏，只有`optional`命中时列出全部命中项，`reason`按声明顺序换行连接；选项级`unavailable`（`hide`／`disable`）是未被显式`mode`约束条目的默认模式，与`hide_when_unavailable`互斥。
普通单件安装结果按真实部位读取`Equipment.WEAR_TEXTS`并代入具体装备名；这组正文属于跨事件共用内容。新增普通单件可安装部位时必须同步提供正文，不能退回“已装在某处”的机械占位句。事件定量恢复角色当前魔力使用`mana_gain`，完整恢复至当前上限使用`mana_restore_full`；直接补充贴身魔瓶使用`flask_mana_gain`，不冒充手动存入，也不改变角色当前魔力。

普通与多阶段事件都可使用`install_random`；普通事件在进房时、多阶段事件在进入对应阶段时将生成器展开为具体安装效果，查看与提交不重抽。`special_install_random{types,replace?,fallback?}`同样只会冻结当前有合法位置的性玩具。省略`fallback`时，没有任何空余位置就不生成该选项；不能暗中改成另一种奖励，也不能挤掉原装备。实际安装结果统一读取具体类型的`wear_text`，不会显示“某件性玩具”或等级泛称。

需要为现有数值效果抽取整数时使用作者层`random_amount{effect,minimum,maximum,source?}`。它只包装`mana_loss/mana_gain/flask_mana_gain/pressure`，进入事件或阶段时沿`event`随机域取包含上下限的整数，立即展开为普通定值效果；运行状态、候选与快照不保存生成器。`source`只允许配合`pressure`，不得把遗物、卡牌或任意脚本塞进随机数值接口。

仅用于封闭剧情演出的“先取下原性玩具、结束后装回”不改变状态：正文按真实装备名单独描写即可。只有取下期间会开放选择、影响空位或参与规则判定时，才使用`hold_special/restore_held`并接受存档与原子复核。

阶段数组只允许向后引用或进入`result`，不能循环。`next`还可以写成跨事件对象`{"event":"已登记事件id","node":"该事件的节点id"}`：提交后同一个`room_event`实例改写为目标事件的`id`与`stage`，形成事件链，`values`计数与`held`暂存在整条链上继续共享，暂存`key`必须整条链唯一（跨定义重复由加载期的整包校验拒绝，`cleanup_effects`也不能引用别的定义建立的`key`），`cleanup_effects`取整条链的并集并按`key`去重、离开时各执行一次，`chain`键只在真的发生跨事件跳转时写入并记录已经走过的事件id（抵达时不含该键），链上经过的目标事件都会加入`event_seen`，事件携带的遗物按目标事件的定义重算（目标没有遗物奖励选项或遗物池为空时置空，不会发出来源事件的遗物）。跳转目标必须已登记，事件不能引用自身；回到链上已经走过的事件会被拒绝，该选项保留但不可用并显示“这段事件已经走过，不能再回头。”。链能力可用，但当前 12 份迁移内容都不使用链。起始阶段必须允许默认拒绝，或明确提供一个无条件、无效果且直达`result`的免费离开选项；后续阶段若全部选项在当前状态下都无法成立，则进入它的上一步候选也会被拒绝。当前带卡牌三选一或遗物奖励的选择必须直接结束事件。

所有普通与多阶段效果都由同一`apply_effects/describe/describe_result/Snapshot.effect`处理。新增能力先检查能否组合阶段、生成器、现有效果和收尾；确有缺口时增加可跨事件复用的字段，不得增加按事件ID、人物名或剧情名判断的分支，也禁止执行任意字符串脚本。

事件战斗沿正式敌人实例、行动候选、回合、结算与战斗遗物生命周期运行。胜利效果在选择时预演并随事件保存，击败全部敌人后再次复核并原子发放；`requires_defeat:true`不会把装备空间耗尽视为胜利。事件战斗计入遭遇与胜利次数，但跳过普通随机战利品和战后整备，随后恢复原事件的结果页。当前只允许普通事件选项声明该字段；需要分阶段战斗时先扩展同一接口，不能在某个事件中硬编码。

事件道具组沿`event`随机域在进房时冻结，每组只抽一件；查看、读档或打开战利品界面不重抽。战利品行保存稳定分组ID、具体道具ID和领取状态；每次领取都重新检查当前随身容量。继续会丢弃所有未领取行并沿事件完成路径直接返回地图，不能复用普通战斗的超容量领取、整备或`pack`阶段。

### 7.4 离开与钥匙限制

节点`allow_refuse:true`时自动追加保留 ID `refuse`：损失至多10魔力离开，无奖励，魔力不足扣剩余全部。不要手工再增加同名选择。`allow_refuse:false`可完全禁止默认离开；若需要免费离开，作者新增一个无奖励、空`effects`并直达结果的选项。多节点定义的起始节点必须能离开。其他离开惩罚仍须由已登记效果组合表达，不能只写 `exit_mode`。

早期设计记录（**当前校验不接受**`wager`配方与`reward: "keys"`，不要写进内容包）：wager 复用全局三钥匙定义，不能在一个事件里直接改成独立概率：进房固定一枚有效钥匙，各选项成功率1/3，选择一次后直接结算。接受赌局后不能使用卡牌／道具穿插改变装备。

- 左：成功解除至多两把现有锁，优先新皮带；失败加入卡组的虚无诅咒「慌乱」。
- 中：成功获得2次开锁针；失败将本次眼罩加固一档。
- 右：成功获得固定的未拥有遗物；失败将本次皮带加固一档并增加既定压力。

成败都保留本次眼罩与皮带；有效钥匙不能出现在玩家 ViewModel、提示或隐藏意图日志中。其他赌局优先使用通用`nodes/outcomes`；只有确实需要现有接口无法表达的新规则时才扩充共享能力。

## 8. 塔路分布约束

当前一幕：7列、15层普通房间、6条路径，之后第16层固定首领六缚、第17层出口。普通路径每步只连下一层、横向至多移一列，禁止交叉与跨层捷径；前两条路径起点不同，生成后清理冗余起始分支。

玩家第1层固定普通战斗、第9层宝箱、第15层休息；前5层不出现休息／精英，第14层不出现休息以避免接第15层火堆。父子房间禁止连续相同的休息／精英／商店。分叉选项尽量类型不同，普通战斗回退可能重复，不承诺每个分支全异。

`ROOM_RATES` 商店5%、休息12%、事件22%、精英8%，其余战斗；这是按节点数形成并打乱的候选袋，再经过限制分配，不是每个节点独立掷百分比，也不保证玩家某条路线恰好达到比例。精英最终转换为带精英遭遇的 battle 房。

新增房型须同时接生成约束、房间字段校验、进入／离开、地图图标／说明和测试；不要用固定楼层表重建第二张塔。
