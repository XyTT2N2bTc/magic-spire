# 可直接接入的内容模板

适用项目：本目录所属的 Godot《紧缚尖塔》，2026-09-07，内容格式版本 **1**（`event` 自 2026-09-16 起为 **2**，见 §3）。这五类文件已经由游戏读取；按以下字段填写即可接入已有机制，不需要修改注册表或复制规则代码。

## 放在哪里、怎样启用

1. 从 `templates/` 复制所需 JSON；每个文件只放一条内容，可以只复制一种。
2. 改成自己的 `id`、名称、说明和数值，再放进 **`content/packs/你的内容包名/`**。文件名可自定，建议与 id 相同。
3. 在项目根目录运行 `powershell -ExecutionPolicy Bypass -File tools/check-content.ps1`。显示 `CONTENT PASS` 才表示字段、范围和引用全部通过。也可用 `-Path 路径` 检查一个尚未启用的文件夹。
4. 完全退出并重启游戏，再开始新局。主页的“内容包”显示加载数量；点击可以查看目录或错误。

`templates/` 是样例库，不自动启用。`packs/` 中的 JSON 及子文件夹会自动读取；停用时把文件移出该目录，或把扩展名改成 `.disabled`。不需要重新编译游戏，也不支持运行中热加载。

当前启动器／编辑器使用项目内的 `content/packs/`。未来导出可执行程序后，加载器使用**可执行文件旁的 `content/packs/`**；需要随发布包一起复制该目录。本次验证针对当前源码运行版，没有制作或验收导出安装包。

所有文件先一起检查，再一次性登记。任何一个文件错误，这一批外部内容**全部不启用**，主页会说明问题，游戏使用内置内容。文件最多256个、每个最多1MB、子文件夹最多8层。不读取或执行包内脚本。

## 五类模板与实际来源

| 复制的文件 | `kind` | 正常游戏里的来源 |
|---|---|---|
| [restraint.json](templates/restraint.json) | `restraint` | 加入指定敌人的普通安装和最终安装池；现有枚举全部普通模板的警卫方案也会识别 |
| [special_equipment.json](templates/special_equipment.json) | `special_equipment` | 自动附带一个地图事件，选定选项后通过正式事务装备到指定特殊子位置 |
| [event.json](templates/event.json) | `event` | 加入地图事件池，进房时生成并冻结选项 |
| [relic.json](templates/relic.json) | `relic` | 加入商店、宝箱、事件共用的遗物奖励池，仍排除已经持有的遗物 |
| [enemy.json](templates/enemy.json) | `enemy` | 自动建立一个单敌遭遇，加入弱怪或强怪池 |

“加入池”表示有概率出现，不保证每局出现。加载器不抽游戏随机数；同一份内容、同一种子保持可复现。改动包内容、文件顺序或 ID 后不保证旧种子的地图不变。

## 共用字段

| 字段 | 要求 |
|---|---|
| `schema_version` | 数字：`event` 为 `2`，其余四类为 `1` |
| `kind` | 上表之一 |
| `id` | 3—64位小写英文、数字、下划线，首位必须是字母；建议 `作者名_内容名`。不得与同类内置内容或其他包重复 |
| `name` | 1—60字的日常名称；不是状态或行为判断条件 |

事件可选字段`pool`默认为`true`；填写`false`时仍保留完整定义供独立练习或回归验证调用，但不会进入正常爬塔随机事件池。是否入池只控制随机来源，不改变事件内的候选、效果与结算。

只接受模板说明中的字段。拼错字段、未知效果、空引用、越界数值会报错，不能通过随意加字段实现新机制。JSON 不支持注释、尾逗号或函数；请使用 UTF-8。文字使用普通文本，不写方括号富文本标签。介绍／说明最多1200字，选项名称最多80字。

## 1. 拘束具

必填：`base_template`、`slots`、`enemy_sources`。名称与允许部位可以改；材料、解除方法、上锁资格和等级数值沿用基础模板。普通单件的大臂三档自动肩带及相应躯干固定仍由现有规则生成，不会因为换了名称而跳过。所有三档触发的额外添加／补回仅限普通单件；复合拘束具不适用，不能用套体加固来恢复已经解除的肩带。

| `base_template` | 含义 | 可选 `slots` |
|---|---|---|
| `rope` / `belt` | 绳索／皮带 | `upper_arm`、`forearm`、`wrist`、`palm`、`thigh`、`calf`、`ankle`、`foot` |
| `cord` / `fine_belt` | 细绳／细皮带 | `palm`、`fingers`、`foot`、`toes` |
| `tape` / `cable_tie` | 胶带／扎带 | 上述肢体槽的并集 |

部位含义依次为大臂、小臂、手腕、手掌、大腿、小腿、脚踝、脚掌；`fingers` 手指，`toes` 脚趾。`slots` 必须非空、不能重复、不能超过基础模板的范围。手部／足部是合并显示入口，不能拿来当安装槽。精准安装点、外层遮挡、容量、躯干固定与复合封闭检查由原规则决定。

`enemy_sources` 填敌人**类型 id**，例如 `belt`、`rope`，也可以填同批新敌人的 id。必须是继承绳索／皮带行为的敌人；至少一个。该新拘束具加入这些敌人的两种安装池，仍按原计划选择合法目标和等级。

本版不通过此文件增加复合结构、链接结构、眼／嘴特殊结构、肩部连接规则或新材料。现有复合装备可以通过事件的 `locked_assembly` 配方出现；需要新结构时按旧设计文档补底层能力与测试，不能用普通槽伪装。

## 2. 特殊部位道具

必填：`base_type`、`energy_gain`、`turn_gain`、`duration`、`wear_text`、`acquisition`。可选 `design`。

| 字段 | 要求和实际效果 |
|---|---|
| `base_type` | `placeholder_1`、`placeholder_2`、`placeholder_3`，用于继承当前固定设计 |
| `energy_gain` | 0—100；每次行动实际支付能量触发一次，不按花掉的能量点数重复 |
| `turn_gain` | 0—100；每次玩家回合开始增长一次 |
| `duration` | 0—100整数；有 `turn_gain` 时必须大于0，没有时必须为0 |
| `wear_text` | 1—400字的通用佩戴正文，必须恰好包含一次`{name}`；事件结算时替换为该性玩具的准确名称，供所有事件复用 |
| `acquisition` | 包含 `name` 事件名、`intro` 介绍、`label` 装备选项名、`slot` 指定安装位置 |

两种增长不能同时为0。只有回合效果时，到期移除装备；同时有能量效果时，到期保留装备和能量被动。当前采用现有的**有耐久、可解除**特殊装备规则，不恢复早期无耐久方案。

自动事件 id 为 `装备id_arrival`，请勿另建同名事件。它和其他事件一样遵守拒绝费用、回合边界、容量检查及事件后离场流程；没有额外隐形奖励。当前槽满时选项说明原因，不会挤掉原装备。

`design` 可以只覆盖下列部分字段，其余继承基础类型：

| 字段 | 可填值 |
|---|---|
| `grade` | 1—3整数 |
| `maximum` | 最大耐久1—1000 |
| `ratio` | 初始耐久比例0.01—1 |
| `damage_factor` | 受到的解除伤害倍率0.01—10 |
| `slots` | 非空允许位置数组，见下表 |
| `methods` | 非空数组：`strain` 挣扎、`slip` 滑脱、`magic_slip` 魔法滑脱、`lower` 降档、`focus` 找松处、`manual` 特殊手动取出 |
| `tools` | `shard` 小石片、`saw` 锯条；允许空数组 |
| `environments` | `wall` 墙壁类、`sharp` 尖锐类、`hook` 挂钩类（统一表见 `data/environments.gd`；仍需真实来源及接触）；允许空数组 |

| 特殊区域 | 子位置 id | 各位置容量 |
|---|---|---|
| 乳头 | `special_1_a` | 2 |
| 肉棒：柱身、龟头、冠沟、马眼 | `special_2_a`、`special_2_b`、`special_2_c`、`special_2_d` | 2、2、2、1 |
| 双穴：小穴、后庭 | `special_3_a`、`special_3_b` | 1、1 |

数组不允许重复。`acquisition.slot`必须属于最终`design.slots`。允许某种方法不代表随时能用，仍受姿势、辅助、真实接触和外层条件限制。挂钩、尖锐处和墙面只负责满足现有卡牌的环境条件，不会生成直接拆除动作。

## 3. 事件

事件只有**一种结构**：定义填写`start_node`与`nodes`，数组顺序即作者顺序。完整可复制文件见[templates/event.json](templates/event.json)（单节点）与[templates/event_multistage.json.disabled](templates/event_multistage.json.disabled)（多节点；`.disabled`不会被加载）。本节只列字段与写法，不再复制第二份完整 JSON。

| 定义字段 | 要求 |
|---|---|
| `schema_version` | 事件固定为数字`2`（其他四类仍为`1`） |
| `start_node` | 起始节点`id`，必须引用`nodes`中的某一项 |
| `nodes` | 1—12个节点的数组，顺序即作者顺序 |
| `cleanup_effects` | 可选，最多8项；只接受`restore_held`，且每个`key`都必须在某个节点的选项里建立过 |
| `kind`／`id`／`name`／`intro`／`pool` | 见共用字段；`intro`为事件开场正文 |

单节点定义（今天内容里的普通事件）的节点`id`必须是`choice`，并且不写`title`／`intro`。多节点定义的节点`id`不得使用运行时保留字`choice`／`reward`／`result`／`battle`／`loot`／`keys`，并且必须写`title`（最多60字）与`intro`。多节点定义的起始节点必须能离开：`allow_refuse`为真，或包含一个无条件、无效果、直达结果页的免费离开选项。单节点定义没有这条限制——交换类事件可以只提供必须完成的选项。

### 节点声明

每个节点都必须写全下列声明，取值只有表中这些：

| 字段 | 取值 | 含义 |
|---|---|---|
| `allow_refuse` | `true`／`false`，**无默认** | 为真时该节点自动追加支付至多10魔力离开的`refuse`选项；为假则进入后必须完成一个合法选项。不得重用`refuse`作为作者选项 id |
| `unavailable` | `hide`／`disable` | 该节点选项无法执行时的默认处理。单节点现状值`disable`（保留选项并给具体原因），多节点现状值`hide`（不生成） |
| `relic_gate` | `pool`／`claimed` | 遗物闸门的位置。单节点现状值`pool`（冻结前查未持有遗物池），多节点现状值`claimed`（冻结后查本事件是否已冻结到遗物） |
| `random_freeze` | `generators`／`always` | 生成器的冻结时机。单节点现状值`generators`（只有含生成器才冻结），多节点现状值`always` |
| `outcome_draw` | `option`／`selection` | 加权结果的抽取粒度；两种现状值都是`option`（选择器外抽一次，再把同一结果复制给每个所选实例） |
| `frozen_form` | `in_place`／`staged` | 冻结选项的字段布局。单节点现状值`in_place`（作者对象就地更新），多节点现状值`staged`（固定字段序）。必须按形态填写；B2 起运行时按声明执行，现状由节点数决定 |
| `empty_node` | `allow`／`fail` | 节点没有任何能够执行的选项时。单节点现状值`allow`（保持零候选），多节点现状值`fail`（返回具名原因） |
| `choices` | 1—6个选项 | 选项字段见下 |
| `title`／`intro` | 仅多节点 | 节点标题（最多60字）与节点开场正文 |

### 选项字段

每个选项必填`id`／`label`／`reward`：`id`是该节点内唯一的小写英文 id，`label`是按钮文案（最多80字），`reward`只接受`none`（无额外奖励）、`common`（普通牌三选一）、`uncommon`（罕见牌三选一）、`rare`（稀有牌三选一）、`relic`（随机未持有遗物）。其余字段可选：

| 字段 | 取值与适用形态 |
|---|---|
| `recipe` | 见下表的三选一配方；与`effects`不能同时出现 |
| `effects` | 最多12项效果，按顺序在同一事务内执行；允许空数组，带奖励的选项也可以用空效果 |
| `outcomes` | 2—8个加权结果；**B2 起生效**，当前只写进多节点定义的节点 |
| `next` | 指向后续节点或`result`；**B2 起生效**，当前只写进多节点定义的节点。多节点内只能向后，不能倒退或循环；带奖励的选项必须写`result`（领奖后结束事件） |
| `when` | 按事件`counter`或`selector`可选数量显示分支；**B2 起生效**，当前只写进多节点定义的节点 |
| `result_status` | `success`／`failure`／`neutral`，缺省`neutral` |
| `report` | 提交后的事件正文；省略时使用`label` |
| `report_variants`／`detail` | 条件正文／选择前说明；`"detail": ""`明确省略注语 |
| `selector` | 在当前卡组或实际佩戴的拘束具上展开（见下） |
| `availability` | 状态条件；单节点与多节点都生效（见下） |
| `hide_when_unavailable` | 布尔值；完整效果序列当前无法原子成立时不生成该选项。**B2 起生效**，当前只写进单节点定义的节点 |
| `encounter`／`item_rewards` | 战斗／道具奖励选项（见下） |
| `show_pressure_sources` | 布尔值；按效果顺序把已冻结的`pressure.source`作为结果正文显示 |

`recipe`与`effects`至少要有一个，或者只写`outcomes`；`recipe`与`effects`不能同时出现。配方若在当前状态下没有完整合法方案，该选项不会出现。显式效果选项会保留，但当前不能完成时显示具体原因。奖励池为空时，随机遗物选项不出现。

| `recipe` | 已实现行为 |
|---|---|
| `free_basic` | 给空闲部位安装初级普通装备 |
| `tighten_or_medium` | 优先加固现有目标，否则安装中级普通装备 |
| `locked_assembly` | 安装合法的现有复合装备并锁住指定组件 |

早期设计记录里的`wager`配方与`reward: "keys"`**当前校验不接受**，不要写进内容包。

`effects`支持：

| `op` | 其他必填字段 |
|---|---|
| `install` | `template` 已登记普通装备、`slot`、`grade` 整数1—3、`tier` 整数1—3、`locked` 布尔值；必须符合基础定义 |
| `special_install` | `type` 已登记性玩具、`slot` 为该装备允许的精准位置 |
| `mana_loss` | `amount` 0—100，实际魔力不足时不能选择 |
| `mana_gain` | `amount` 0—100，恢复魔力但不超过角色当前上限 |
| `mana_restore_full` | 无额外字段；将角色当前魔力恢复至当前上限 |
| `mana_max_loss` | `amount` 1—100整数；永久降低最大魔力，当前魔力高于新上限时同步压低；不得令上限低于1 |
| `flask_mana_gain` | `amount` 0—100，直接增加贴身魔瓶储量；不受角色魔力上限约束，也不占用手动存入次数 |
| `pressure` | `amount` 0—100，增加快感；达到100时使用现有高潮与魔力损失规则。可填`source`及按特殊装备族选择的`source_variants` |
| `card` | `type` 已有卡牌 id |
| `tool` | `type` 已有道具 id |
| `relic` | `type` 已登记遗物 id，不能重复领取 |
| `transform_card` | `target: "$selected"`、`type`；把卡牌选择器选中的永久卡牌原位改成指定牌，保留实例编号 |
| `remove_card` | `target: "$selected"`；从卡组及当前牌堆移除卡牌选择器选中的同一实例 |
| `remove_restraints` | `targets: "$selected"`；配合多目标拘束具选择器，将所选1—4件拘束具原子完全解除 |
| `ease_restraint` | `target: "$selected"`；解开所选拘束具的锁并松一档，一档时解除 |
| `counter` | `key`、非零整数`amount`；只记录本次事件内的计数，不直接改角色资源 |

多节点节点还可使用生成器效果，它们在进入事件或节点时冻结为普通具体效果，查看、存档与提交都不重抽：

| `op` | 用途 |
|---|---|
| `install_random` | `templates`／`count`／`grade`／`tier`／`locked`；依次冻结1—4个不同的合法安装结果。可选`allow_links: false`把本次生成严格限制为普通单件；由人物亲手佩戴时默认`wear_style`为`assisted`，附魔拘束具自行缠上时明确写`animated` |
| `tighten_random` | `count`／`to_tier`，可用`templates`过滤；依次选取1—4个尚未达到目标档位的真实拘束具 |
| `special_install_random` | 从`types`列出的性玩具中冻结一个当前合法实例；可选`fallback`。不写后备效果且没有合法空位时，该选项不生成 |
| `random_amount` | `effect`／`minimum`／`maximum`，目前可包装`mana_loss`／`mana_gain`／`flask_mana_gain`／`pressure`；冻结成一个普通定值效果，整数范围0—100且包含上下限。仅包装`pressure`时可附`source` |

`hold_special`（`key`／`slots`）暂存与指定特殊部位相交、且没有连接的现有性玩具；`restore_held`（`key`）把对应暂存实例原样装回，只允许出现在定义级`cleanup_effects`。同一`key`只能建立一次，并且必须在`cleanup_effects`里恰好归还一次。

`selector`既可写在选项上，也可用于`when`的条件来源。选项级选择器在当前卡组或实际佩戴的拘束具上展开；正文中的`{name}`／`{slot}`／`{type}`和效果中的`$selected`会冻结为所选实例。可选`count: 1—4`指定同时选择数量；拘束具可用`include_special: false`排除性玩具，卡牌可用`exclude_curses: true`排除诅咒。

`availability`是状态条件，角色状态不满足时选项保持显示但不可选择，`reason`只在按钮悬浮／聚焦的二级说明窗中显示，正式提交前会再次复核。条件按`kind`分两种，键集固定：`{"kind": "no_chastity_lock", "reason": "……"}`（佩戴任一平板锁时生效，不检查上锁状态）；`{"kind": "has_relic", "type": "已登记遗物id", "reason": "……"}`（尚未持有该遗物时生效）。存档校验按同样的键集复核。条件叠加与规范拼写`conditions`／选项级`unavailable`／`mode`**B2 起生效**，当前不接受，不要写进内容包。

选项及随机结果的`report`可另配`report_variants`，快感效果的`source`可另配`source_variants`。每项格式为`{"when": {"kind": "equipped_special_family", "value": "已登记family"}, "text": "条件正文"}`；进入事件／节点时按当时仍在佩戴的特殊装备族选中第一项匹配正文，并冻结为普通`report`／`source`，存档、查看与提交都不会重选。该接口只替换文案，不修改效果、次数、奖励或资格，也不能按事件 id 或中文装备名判断。

选项可声明通用`encounter`对象，把本房事件临时切换为一场正式战斗。必填字段为：`id`引用已登记遭遇，`requires_defeat`决定能否以装备空间耗尽结束，`victory_effects`填写1—8个胜利后效果，`victory_report`填写胜利正文，`result_status`填写`success`／`failure`／`neutral`。这种选项的`reward`必须为`none`；战斗胜利后直接回到事件结果页，不生成普通战后卡牌、道具、遗物奖励，也不进入整备。选择时及胜利时都会复核效果，不能用事件ID专用逻辑补发奖励。

选项还可声明`item_rewards`，包含1—6个`{id, pool}`分组；每个分组从所列现有道具ID中冻结一件。选择后进入共用战利品界面，每件单独领取或放弃；领取时若随身容量已满，该行直接显示具体原因并禁止领取。继续后直接完成事件，不进入战后整备或整理道具。该字段要求`reward: "none"`，不能与`encounter`或`selector`叠加。

按钮已写清的动作、收益和代价不再重复到注语中。确定结果的选项可填`"detail": ""`明确省略注语；省略字段仍使用精简的效果／奖励预告。随机`outcomes`继续要求非空公开预告，保留概率、奖惩和必要的后备代价，不展示已冻结结果。离开选项通常无需注语，不写空位隐藏规则、读档随机机制或状态不变等说明；这些由实际资格和各自信息窗口承担。结果正文写发生了什么，公共收尾按钮使用“离开”。

删牌、换牌和解除所选拘束具的结果由`report`代入`{name}`写清，公共模板不再追加同义结果句。仍会补充随机取得的具体奖励、最终资源数值和动态档位等正文未涵盖的实际信息。

多节点定义按`nodes`顺序推进：进入一个节点时冻结该节点全部选项，提交后按`next`前进或结束事件，最后执行`cleanup_effects`。每个加权结果、随机数值、随机安装位置和随机收紧目标都沿独立`event`随机域冻结成普通具体效果；查看、打开地图、存档与读档均不重抽，正式提交仍按候选版本原子复核。某个选项无法完整成立时只隐藏该选项；若下一节点会没有任何合法选项，上一节点的该选项在候选阶段就不可用。每个结果页只属于本次提交的选择，前一次结果留在日志里，不会在下一页重复播放。

`when`只能读取本事件由`counter`写入的非负整数，或读取现有`card`／`restraint`选择器的可选数量；它不能按事件名、正文或任意状态执行脚本。未知操作名整包拒绝；不要为某个故事创建专用`op`。

跨事件跳转（`next` 写成`{"event": "...", "node": "..."}`）与事件链**B4 起生效**，当前不接受，不要写进内容包。

普通单件拘束具的事件结果按`wear_style`读取`data/equipment.gd`中的人物协助／活化拘束具两套正文，并按真实安装部位代入具体装备名。不得把带“她”的人物协助正文用于床具、陷阱或附魔拘束具自行施加的场景；新增可安装部位时必须同时补齐两套正文。作者正文只负责事件人物和场景，不重复拼接“装在某部位”的通用句。复合、链接与性玩具继续使用各自结构文案。

封闭演出中若只是为了描写接触过程而暂时取下、结束后立即装回原有性玩具，且中间不开放玩家行动、也不改变占位或判定，只在正文中写出准确装备名，不修改装备状态。只有暂时空出的部位会真实影响后续安装或其他规则时，才使用`hold_special`／`restore_held`。

可引用同批其他文件，文件名不决定引用先后。基础卡牌 id 可查 `data/balance.gd:CARD_NAMES`；现有道具为 `shard`、`saw`、`picks`、`return_seal`。引用成功不豁免原物品的使用条件。

当前仍未开放事件出现权重、仅出现一次、任意脚本条件、任意状态写入或自定义离开费用；单节点定义是否提供付费离开只由节点`allow_refuse`决定，多节点定义的起始节点必须能够离开。未知操作名整包拒绝；不要为某个故事创建专用`op`。

## 4. 遗物

必填：`rarity`、`detail`、`modifiers`。`rarity`只允许`common`（普通）、`uncommon`（罕见）、`rare`（稀有）；缺失或未知值整包拒绝。分类用于图鉴显示及普通50%／罕见33%／稀有17%的一般遗物抽取；宝箱依大小另用分布。价格保持原魔力价格。描述必须与真实效果一致，至少填写一种已实现加成或下述 trigger：

| 加成 | 范围 | 效果 |
|---|---|---|
| `capacity` | 1—10整数 | 增加随身道具容量，身体限制照常生效 |
| `battle_mana` | 1—100 | 普通及特殊战斗结束恢复额外魔力，受魔力上限限制 |
| `preparation_turns` | 1—10整数 | 延长正常战后整备，不延长休息室或巡视 |
| `strength` / `dexterity` | 1—10整数 | 常驻力量／灵巧；力量同时影响全部体术，每段计算 |
| `leg_dexterity` | 1—10整数 | 仅腿、脚踝、足部灵巧；包含被动滑脱 |
| `opening_draw` | 1—10整数 | 每场首个玩家回合额外抽牌 |
| `turn_draw` | 1—10整数 | 战斗、牢房、休息与整备的每个玩家回合开始时额外抽牌 |
| `opening_mana` | 1—100整数 | 每场开始恢复魔力 |
| `retain_energy` | 固定为1 | 正值即开启本场剩余能量保留，不按数值重复倍增 |
| `single_hand_cast` | 固定为1 | 手部施法条件由双手完整自由放宽为任意一只手的手掌与手指均自由；火球术手势加成共用，不影响工具握持或手部辅助 |
| `pickup_mana_max` / `pickup_mana` | 1—100整数 | 拾取时一次性永久上限增加／恢复；先上限后恢复 |
| `mana_energy_step` | 1—100整数 | 可出牌阶段累计魔力损失达到阈值获得1能量，余数本场保留；多个来源按现有加成表合计阈值 |

上述开场、首回合、回合内与结束效果均包含牢房、休息和整备。指定trigger.phase=battle同样包含特殊战斗；巡视只暂停。stage仍不开放任意脚本。

同一文件可以组合这些加成。默认加入遗物奖励池，不提供 `enabled`／`weight`／`price` 字段；商店继续按现有遗物价格售卖。可选 trigger 复用正式按次触发接口；没有固定加成时 modifiers 可以为 {}。trigger 必填 event、scope、op：event 支持 strain_destroyed／card_slipped／magic_paid／fell，scope 为 turn／battle，op 支持 charge／draw／mana／posture_discount。charge／draw 使用1—100整数 amount；mana 只用于 magic_paid，使用大于0且不超过1的 ratio，不写 amount。posture_discount 使用 amount、from、to（stand／sit／lie），只支持 fell＋turn，沿用本回合一次的共享姿态优惠。可选 phase 为 battle／prepare／rest／prison；card_slipped 可限定整数 from_tier／to_tier（1—3，目标须仍存在）。每件遗物仅一条 trigger；未知字段、事件及不支持的组合整包拒绝。示例：{"event":"magic_paid","scope":"battle","phase":"battle","op":"mana","ratio":0.5}。不得自行添加未登记的 modifiers 名称。

## 5. 敌人

必填：`base_enemy`、`hp`、`order`、`strength`、`encounter`。

| 字段 | 要求 |
|---|---|
| `base_enemy` | `rope` 绳索、`belt` 皮带、`tape` 胶带、`cable_tie` 扎带、`gag` 口球、`toybox` 玩具箱、`lock` 漂浮锁 |
| `hp` | 1—1000整数 |
| `order` | 0—1000整数；越小越先安排 |
| `encounter.rank` | `weak`／`strong`；前三次已完成的普通战斗使用弱池，此后强池 |
| `strength` | 1—1000整数；弱怪允许1或2，独立于生命、装备等级和伤害 |
| `encounter.grade` | 1或2；仍遵守该行为自身的装备／阶段规则，不保证覆盖所有阶段的等级 |

敌人的行为、阶段、意图重选和图片继承 `base_enemy`，名称和生命使用新值。自动遭遇 id 为 `敌人id_encounter`，含一个该敌人；不能与已有遭遇重复。需要让新敌人施加新拘束具，在对应拘束具文件的 `enemy_sources` 写这个敌人的 id。

本版不开放自写脚本、全新行动、精英／首领分类、多敌编队编辑或自定义图片路径；这些需要在正式行为系统补接线和测试。

## 交给其他 AI 时的要求

请同时提供本说明与需要的 JSON 模板，并要求：

> 仅使用本文支持的字段，输出可解析的 UTF-8 JSON，每文件一条内容。为所有条目使用独立英文小写 id，中文名称与效果说明保持简短准确。只能组合现有机制，不发明未实现的效果字段。说明每个文件会从哪个正常游戏入口出现；用检查命令验证全部文件及跨文件引用。如果需求超出本文，列出需要新增的引擎能力，不把它伪装成已接入。

## 存档与验证边界

重启只负责加载定义，不改写已经冻结的地图、遭遇或事件，因此测试新出现内容应开新局。已保存的新装备、敌人意图、特殊道具剩余次数和事件效果继续使用原存档流程。同一套定义仍在时可以继续；删掉或改掉正在被存档引用的定义可能导致该存档被拒绝，不会静默替换或删除其中物品。本 Demo 不迁移旧内容包存档。

字段校验不会理解中文说明是否诚实，也不会证明任意新数值都平衡。发布内容前仍应实际测试它的选择／获得、使用／解除、失效、读档和相关不可用原因。基础接入的自动案例位于 `tests/content_cases.gd`，运行 `tools/check.ps1 -Suite content`；涉及新底层机制时按其对应分类补测试。

现有弱怪行为：普通材质为“初级2档施加→加固／补施加→准备→中级2档附着离场”；口球为“准备→准备→初级2档附着离场”；玩具箱为“准备→佩戴→停顿”循环。玩具箱读取统一初级性玩具随机池：飞机杯不随机生成，外置震动棒只在中级池。多面手按当时可成立的控制分支随机选择上锁或双重加固；这套行为仍由内置代码维护，当前JSON敌人模板不能声明。

弱怪入场按当前装备过滤并累计到总强度2；strength允许1或2，可为两只强度1或一只强度2，允许同种重复，强度不在前台显示。口部占用排除口球，无未锁可上锁装备排除漂浮锁。完整筛选与回退见docs/first-floor-enemy-library.md。漂浮锁只做预告／上锁循环，不会生成其他装备。内置杂乱拘束具的加权行动仍由代码配置，本JSON模板不新增动作编辑接口。


拘束施加采用同一三档优先级：空手腕→空嘴部／手指→其余合法新增（包括脚掌、脚趾、已有装备追加、链接）。来源先限定允许模板，最高档内随机选择。以rope为base_enemy的派生敌人继承含link_rope的初始／最终池；链接必须已有真实两端，不免费补端。其他材质基类不会自动获得链接。显式事件安装位置保持原声明，批量随机普通施加逐件按同一部位优先级冻结具体位置。

余烬晶石使用 {"event":"paid_cast","scope":"turn","op":"guarantee","amount":1}：每回合首次耗魔施法必定成功。仅支持此事件、周期与数量组合；仍须满足施法部位和支付要求，免费复放不占机会。
