# 人物台词与行动日志替换

人物行动台词集中维护在 `data/action_copy.json`。保存为UTF-8合法JSON，保留键名，替换右侧文字；重启游戏后加载。当前工程直接运行支持读取；未来制作导出包时须把该JSON加入非资源文件的导出包含项。

正式付费行动按结算时保存的结构化事实选择台词，不从按钮名、日志正文或卡名猜测：快感分为`low`（0—39）、`mid`（40—69）、`high`（70—99或本次行动触发高潮）；取行动前后较高档，避免深呼吸或高潮回落让刚发生的身体反应错档。清晰说话为`clear`，普通／马具口球为`partial`含混短句，胶带封口及假阳具口球为`full`。完全堵嘴统一使用`hero.muffled`，不显示清晰词句或心里话。

卡牌台词按实际牌面分为`card.setup`、`card.magic`、`card.strain`和`card.slip`。真实施法优先于其他效果分类，自由／自身准备面归入运作类。施法已经付款但实际失败时，卡牌改用`card.magic_failed`，固定火球术改用`attack.fireball_failed`；该分支只读取正式施法结果，不改变成功率、费用、随机、效果或牌的去向。

非卡牌付费行动包括上肢体术、腿部体术、火球术、移动／牢房探索、姿态变换、徒手处理拘束具、从小穴／后庭取出跳蛋、安装固定工具、深呼吸和踢击通风口。事件选择、普通道具使用、固定工具使用、挂钩、取回工具、魔瓶存取、结束回合与塔路旅行不因本批获得付费行动差分；姿态等行动实际减费为0时仍保留原有操作结果，不伪造能量支付。

## 已留出的台词位

| 键 | 触发条件 |
|---|---|
| `hero.<行动组>.<快感档>.<说话状态>` | 已提交的分组行动，例如`hero.card.strain.high.partial` |
| `hero.card.magic_failed.*` / `hero.attack.fireball_failed.*` | 已付款且正式判定失败的卡牌／火球施法 |
| `hero.muffled` | 本次操作前或操作后为完全堵嘴，所有行动共用 |
| `hero.climax.<normal/repeated/low>.<clear/partial>` / `hero.climax.full` | 本次正式行动实际触发高潮时的角色发言；完全堵嘴只用共同鼻音 |
| `climax.narration.<normal/repeated/low>` | 高潮时显示在原手牌区的第二人称旁白 |

每次成功提交显示一条最新台词，保留到下一次成功操作；没有逐字播放、语音或额外确认。查看、翻面、拖放取消、失败提交不触发新台词。对话框内可滚动长文本；战斗中带头像与指向人物的尾角，事件中只显示头像对话框。

本次行动实际引发高潮时，高潮发言取代该动作原本的高快感台词，继续显示在人物对话框；第二人称高潮旁白单独投影到原手牌区，不进入对白、状态窗口或行动日志。射精前魔力不足20时使用`low`，同一玩家回合累计第二次及以后或单次连续高潮使用`repeated`，其余使用`normal`。魔力只表现为储存在精液中并随射精流失，不写成与精液并列的液体。

旧的`hero.attack`、`hero.card.bound/free`、`hero.pose`、`hero.calm`、`hero.end`、`hero.item`、`hero.event`和`hero.default`正文已经删除，也不再生成。旧记录若仍保存这些cue，投影时直接忽略，不替换成“嗯……”等占位对白。当前没有新分类的零费普通操作不新增人物对白。

## 行动日志位

`enemy.install/assembly/tighten/lock` 对应施加普通件、施加复合件、加固、上锁；`enemy.charge/capture_prepare/capture` 对应普通敌人蓄力、收押准备、执行收押；`enemy.guard_sequence/delayed/leave/idle` 对应连动期间附属结果、被打断停顿、离场、无合法目标。`enemy.unseen`用于未看清的准备动作。

事件按 `event.<事件ID>.<动作>` 命名，例如`event.binding_cleric.choose`；未单独登记的事件动作走`action.default`。需要定制时可以直接添加已经存在的事件ID与动作组合键，不由正文反推事件逻辑。

行动文案可以使用 `{actor}`（实际行动者名称）与 `{result}`（已经发生的正式结果）。默认保留 `{result}`，显示本次实际施加、加固、上锁或事件结果。可以在前后增添测试描述；人物台词当前是完整字符串，不提供这些行动参数。不要删除JSON引号、把真实换行直接放进字符串，换行写作 `\n`。

状态变化只记录名称、获得／增加／结束及本次数量，例如“施加「皮带增生」，现有1层。”。触发条件、持续时间和完整效果集中在状态窗口；日志使用实际结果，不复用卡牌或状态的完整说明。失败原因与实付费用照常记录，各处只写本处需要的信息。

侧栏最新记录在上，滚动查看最近40条人物/敌人/事件结果；完整原始结果仍在菜单的行动记录中。未来动作编号未配置时使用原结果说明；没有台词元数据的旧存档不伪造历史发言。

侧栏支持收起与固定。未固定时点击栏外自动收起；栏内阅读和滚动不收起。固定后点击其他界面仍保持展开，也能主动收起；右上小按钮重新打开。新记录不会强制打开已收起的侧栏。展开/固定属于界面状态，回合与普通视图刷新保留，重新开始时恢复默认，不修改游戏存档或行动记录。

## 开发扩展边界

`core/action_copy.gd`只解析文本并生成只读显示。正式日志的`data.action_copy`保存cue和当时的actor/result，`data.hero_copy`保存本次说话资格确定后的cue，`data.climax_copy`保存同期第二人称高潮旁白cue；均复用现有日志存档，不新增第二个日志状态数组。后续修改文字会重新呈现已保存cue；没有执行动作、抽牌或重抽随机。

怪物从原敌人执行入口登记，连动子动作沿普通操作入口；事件完成后只登记一条结果摘要，避免同时把内部施加日志和整段结果重复塞入侧栏。新敌人沿现有行为入口能直接得到默认记录；新增行为/台词条件需在对应提交处确定稳定cue，不能用中文正文推断规则或在UI修改游戏状态。需要更细卡牌、情绪或表情分支时，在此接口增加结构化条件。

人物自己的结果直接读取已成功提交的机械日志：伤害、耐久、解除、姿态、工具次数等；费用在本次首条人物结果中显示一次。它们不使用测试台词替代实际结果，JSON文案包也不改这些数值。记录带可选player_action来源标记并随现有存档保存；旧档不回填未经记录的历史。
