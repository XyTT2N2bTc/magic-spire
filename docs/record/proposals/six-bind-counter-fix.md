# 六缚战斗内计数修复

状态：**已实现**（v0.16 六缚计数热修复，2026-09-13；后续并入 v0.17.x 线）。
代码出处：`core/game.gd` 入场时 `next_climax_capture = state.overload_total + spec.climax_capture_threshold`（阈值定义在 `data/enemies.gd` 的 `six_bind` 规格）。

六缚入场时，沿现有敌人实例字段将 next_climax_capture 设置为当前 overload_total＋4。全局累计次数保持，用于其余日志与规则；本次战斗之前的事件、休息、牢房、移动、整备或其他战斗不再消耗六缚的四次额度。逮捕被打断后依旧沿原逻辑将门槛增加1、先恢复原行动。再次入场重新设置门槛。

不新增计数接口或存档字段。快照允许最高为全局累计＋4的未来门槛，并继续拒绝越界、错误公开门槛及非六缚实例上的专属记录。图鉴及对应英文改为明确说明本场战斗。

验证复用 enemies 分类的 six_bind_cases：六种来源阶段×0／3／4／12次历史，通过正式压力结算制造历史；覆盖入场、保存恢复、非法快照原子拒绝、前三次不逮捕、第四次逮捕及下一场重置。原逮捕打断、后续每次再次准备和实际收押案例保持。

这是入场初始化修复，不推测已经生成的旧战斗当时具有多少历史次数；旧存档已在六缚战斗中时，应重新开始游戏以应用新计数。
