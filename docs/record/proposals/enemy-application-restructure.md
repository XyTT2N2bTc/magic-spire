# 敌人施加：拆装收口与替换判定性能（讨论结论与实测）

状态：**讨论结论已定，未落地**（2026-11-05～06，人与协调者对话；决策日志 A61–A80）。
域：`spire-godot` 装备的「装」（放置判定与工厂写入）与「拆」（移除执行与级联），以及敌人施加的候选判定与替换判定（`core/equipment_application.gd`、`core/equipment_replacement.gd`、`core/equipment_replacement_assess.gd`、`core/game.gd` 的装备写入与清理）。
本文件只登记结论、依据与待办；实现计划另行规划并经人批准后才开工。

## 1. 症状

- 满拘束局面敌人回合卡数秒（塔顶六缚、魅魔警卫复合施加、监狱入狱检查）。桌面实测见第 2 节；手机倍率**未在真机测过**。
- 安卓风险（推断，未实测）：Godot 主循环与 GDScript 不在安卓 UI 线程上；单次长计算期间玩家切后台或系统暂停画面时，UI 线程会等待渲染线程，超过 5 秒可能触发「应用无响应」。

## 3. 已定方向（人的裁定）

### 3.1 加减收口：要做（为干净与可维护，也为手机与老机器）

结构：**原因（多个）→ 单一写口 → 后果（两层）**。

- 原因层（松解、伤害、挂钩、事件、遗物、收紧、监狱、施加、替换…）只负责：守卫、目标值、本原因自己的文案与反馈；不自己写后果。
- 写口：耐久一个写入口；成员增删只经工厂与清理。
- 耐久层（写入时立即）：按档位门槛触发，档位判定以 `data/restraint_value.gd::tier_for` 为准（0 档与移除阈值一致）。触发：升入 3 档、3 档原地收紧、降入 1 档、其它跨档、品质变更、降入 0 档（交成员层待移除）。档位内耐久变化无写状态的后果（A72 实测 0 影响）。新装上的件视为从 0 档升入。
- 成员层（提交末结算）：加入与移除事件；移除级联按类别分趟、顺序同现行 `core/game.gd::_cleanup`（肩带→特殊件→普通件→复合件→链接→收尾），级联图无环、最深 3 层，一趟完成；只处理脏件。
- 枚举表三级：时机 → 触发 → 对象类别；只登记有记忆、有随机或需对外通知的后果，其余读时现算。
- debug 构建下保留全扫对账，作为提交后聚合校验；发行包不跑。
- 耦合单向：耐久 → 成员（归零交待移除、升 3 档交加入附属记录），成员变化不回写别件耐久（读码结论，未逐钩子核实）。
- 附属记录四种：肩带（`core/shoulder_links.gd::update_cross` 的交叉是唯一「降档也写状态」的附属后果）、躯干固缚（`core/torso_binding.gd::refresh`）、加固带、复合组件。
- 安装事务内的前置动作（复合件取消重叠固缚、平板锁挤占旧锁）留在工厂事务里，不进结算层。
- 收口时在写口的版本号上留「同状态版本内复用判定结果」：调用结构收口能消掉同一调用方的重复，跨敌人的同状态重复（双警卫 91.7%）只能靠版本内复用消掉。

既有裁定（A64–A69，原计划 rev2，已叫停待按本节重规划）：
- 读档迁移另立旧档兼容层，只由 `core/game.gd::restore_snapshot` 对旧修订调用，整体不在唯一路径判据的扫描面内，另钉调用面（迁移示例 `core/snapshot.gd::migrate_cup_stacks`）；
- 事件暂存（`core/room_events.gd::apply_effects` 的 `hold_special`／`restore_held`）只经统一写口增删，事件逻辑在其上封一层；
- 挂钩松解改调 `core/game.gd::_apply_manual_release`，探针反例即撤回并单列缺陷；
- `core/game.gd::_cleanup` 的 `released` 两档与普通件／复合件两套层规则保留，各以声明表钉住；
- 不设文件行数上限，每片统一报告行数统计表，拆分只按职责；
- 索引跨调用／跨提交保留另立契约任务（待办 T7），本收口不依赖它。

### 3.2 跨版本维护候选池：放弃

依据 A78：按耗时加权每次有效提交作废 90% 以上，误作废 99.6%，维护本身会抵掉收益。

### 3.3 替换：保留现行语义；枚举最小集合与近似先不动

- 「拆了再装」撤回：语义影响面大于预期（替换涉及六缚、魅魔警卫、铁男、玩偶师与玩偶、多面手、绳艺大师与助理、监狱巡视补装；敌人侧由 `core/enemy_plans.gd::application_spec` 统一把关权限）。
- 人：「枚举最小集先不动，回头再说」。近似方案（X1、X2、X1＋兜底）与分层求解只作备选，数据见第 2 节 A80 行。
- 剩余核心问题：快速证明「不可替换」（注定失败的例子要试装几百个集合，兜底救不了）。
- 不改语义的备选（未批准、未实施）：试装局部校验与锚点表外提、按分数下界排序早停、按失败原因剪枝、等价单元去重；需先补测试装内部分段与失败原因分布。

## 4. 待办与未决

- 手机：敌人判定分帧执行或至少先出一帧「思考中」；真机倍率与是否触发「应用无响应」**未测**。
- 重型复合替换在整局里的出现频率**未测**（无整局回放驱动）。
- 埋点盲区：`core/game.gd::_reinforce_equipment` 无写入观测、肩带在宿主记录内；用写入流做判据前须补观测。
- 设计与实现不一致：`docs/design/equipment-design.md` §14.2 写「同值可随机」，`core/equipment_replacement.gd::_plan` 实际同分取深度优先先找到者。待人裁定以哪个为准。
- 拘束优先级未被改动的核对（与 `origin/main` 998a24c 比对：`data/equipment.gd::slot_priority`、`core/equipment_offers.gd::preferred` 零差异，三种子逐字节一致）；少见分支（`toe_cast` 遗物、`fallback_templates`）只靠逐行比对，无专门用例。
