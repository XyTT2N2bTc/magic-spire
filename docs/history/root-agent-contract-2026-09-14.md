## 项目概述

本项目是电脑版优先的网页文字 RPG《魔法少女又白给了》。核心玩法是：玩家在独立小型沙盒中探索环境、处理拘束状态、管理魔力与快感值，并通过解除全部拘束或离开区域达成目标。所有登场人物均设定为年满 18 岁。

当前工作重点是规则框架、牢房 Demo、拘束具随机生成、地图交互与 16:9 游戏界面。不要为了快速展示而绕过已经确立的规则系统。

## 网页端重写架构

- 网页端从当前规则书重新建立实现框架。`game-demo/game/` 是新规则内核的唯一权威写入方；旧 `game-demo/app/*-system.ts` 只作为迁移期遗留文件存在，不得再承接新规则或被页面当作判定来源。
- 页面只保留已确认的 UI 位置关系与视觉资源：顶栏、左侧装备区、中央地图、右侧对白／叙事／日志、左下状态区。React 组件只能消费只读 ViewModel 并派发 Command，不得直接改角色资源、装备图、地图、回合或日志。
- 当前游戏主界面固定为电脑版优先的16:9情境式布局：左侧约20%承载身体／装备并在底部保留“当前状态”；中央工作区由左侧紧凑地图与右侧对白并列，地图默认从视口左上开始显示；右侧上部只放叙事，右下保留合并后的“日志”。地图底部使用“移动／行动／当前地块／道具栏与魔法”四个互斥低高度抽屉，展开后内部采用左右工作区而非旧边栏的上下堆叠；当前地块左侧显示地块与高度层、右侧显示检查和环境操作，测试位置控制只放入右侧测试折叠区。移动只承载人物移动／转向，行动承载姿势及其他身体动作，魔术手召唤与移动归入道具栏与魔法。不得恢复会把侧栏或底部推出视口的1480px四列布局，也不得让对白在中央与右侧重复出现。
- 正式行动管线固定为 `Command → ActionCandidate → ActionTransaction → 版本复核与原子提交 → 状态固定点 → 回合阶段 → 再次固定点 → 结构化事件／只读投影`。测试模式也必须复用这条管线，不能建立调试专用判定。
- 独立测试场是正式场景配置，不是“完全自由开局”的别名。它可以通过不消耗回合、不写事件的测试旁路覆盖输入或注入夹具，但注入后的移动、检查、装备操作和结算必须走正式规则内核；固定种子和命令序列必须可复现。
- 当前规则书中未冻结的高级锁具逐模板效果和完整镣铐框架只保留扩展接口，不得用临时数值放入正式生成池。已归档姿势和旧 Demo 规则不得迁回新内核。
- 新内核的普通单件以装备根ID作为`physicalActionTargetId`，主体、扣件和锁具继续使用独立物理ID。普通根生命周期固定为`active/slack/detachmentBlocked`，松垮承接必须保存稳定双向引用并由统一删除事务级联清理；不得用`physicallyOccupies=false`单独代替完整生命周期状态。
- 普通同部位安装默认进入当前最外普通层；更高`layerIndex`只由真实复合／结构层序或明确测试夹具建立。普通根不得与覆盖同一精准部位的复合根共享`layerIndex`：普通件遇复合根时自动进入其外层，单手套／单腿套默认安装在全部重合根之外，显式同层或向既有外层下方插入必须拒绝；单腿套封口、拘束衣白名单和长型单手套的活动套体封闭区不得被自动选层绕过。长型单手套完整包住手掌／手指后不能在其外侧新增这两处普通拘束；先装的手掌／手指普通件可作为真实内层保留，短型单手套不封闭手部。当前力量／紧度必须先按各自主体比例与收紧层计算，再进行同层0.50聚合；扣件耐久永不折算要求。角色部位检查按复合根全部真实覆盖槽显示，但佩戴总览仍按根去重；复合根不得统一标成普通“贴身层”。
- 床面与地面只允许从场景床对象明确声明的侧边跨越：地面站姿必须在床侧正对床并向前才能进入，床面坐姿／站姿必须位于床侧、面向床外并向前才能离开；床头／床尾和任何倒退跨床边界均禁止。普通坐姿侧边离床使用两回合原子跨承载移动：第一回合保持床面坐姿，第二回合同时进入相邻地面并自动站立；地面坐姿不能直接挪上床。地面站立合法入床时同一步切到床面并自动坐下、立即结束站立移动事务。床面姿势按钮的坐转站只原地改变姿势，不承担离床；React不得自行判断床轴或改坐标、承载、姿势。
- `stepLimit=1`的一格站立移动是正式跳跃：事务必须先提交位移与一次站立自动滑脱，再用更新后的固定点事实进行稳定判定；失败保留位移和滑脱并进入真实`groundingCause=fall`。墙边免判，摔倒只允许由当前朝向正后方的合法床格承接并保持原朝向，否则进入地面仰卧／空间不足坐倒；离床后快感100坐回刚离开的身后床格，入床则按移动方向在目标床格坐下且不追加摔倒。快感100必须在C型资源滑脱后重算强制摔倒，摔倒分支不得再执行自动挣扎。
- 普通绳索、皮带、胶带和扎带的材料数值只能读取`game-demo/game/data/rules.ts`中按规则书14.2A—C建立的注册表。绳索有绳结、皮带有皮带扣、胶带与扎带无独立扣件；禁止为了统一UI给后两者伪造0耐久扣件。
- 胶带干湿是所有真实胶带材质主体的物理状态：普通胶带、胶带眼罩和胶带堵嘴均保存`dry|soaked`，浸湿只对被选中的主体提供紧度－3。普通胶带的干燥粘性继续令其普通滑脱成为可点击必败，浸湿同时撤销该封锁；头嘴胶带仍只使用眼／嘴`fixedValueSpecial`，干燥不额外封锁，浸湿也不新增徒手普通滑脱。正式湿态变化必须进入环境行动事务；测试夹具可以无事件注入，但页面不得获得绕过事务的通用湿态写接口。
- 普通墙面与普通地面不得造成固定主体损伤：真实接触时只可为一个本来存在力量挣扎路线的暴露主体提供正常力量挣扎，绕过自身末端扫描与同层聚合但不绕过层级、锁、材料、姿势、承载、身体侧或接触。普通墙地加成0，碎裂地面具名`+2`；潮湿地面可浸湿真实接触的普通、眼部或嘴部胶带主体。粗糙床面、坚硬桌沿、床簧、螺钉和刀具等明确专用构件仍使用各自固定值。

## 权威信息顺序

发生冲突时按以下顺序判断：

1. 用户在当前任务中的最新明确要求。
2. 项目内最新规则书或规则对照文档。
3. 已通过测试的底层规则实现。
4. Demo 中的旧文案、旧数值和旧界面行为。

Demo 只是规则的实现，不是规则的来源。不得根据旧 Demo 反向修改规则书。

## 工作流程

每次修改遵循以下顺序：

1. 阅读与任务直接相关的规则文档和现有代码。
2. 按`RULEBOOK-VERIFICATION-V044`建立或更新`RuleChangePackage`，列出受影响状态、候选、数值、事务、事件、界面、日志、文案、迁移、随机域、十四交互轴和明确不受影响项。
3. 先写最小正例、最近反例、边界、回滚和必要交互案例；尚未实现的案例明确标记预期失败，不得伪装成绿色回归。
4. 先修改规则数据与纯逻辑，再修改事务、固定点和界面表现。
5. 任何新增或修改的规则、设定、状态、装备、环境、物品、行动、结果或界面入口，都必须在同一批次检查其玩家可见文案，并补全或修改对应的UI标签、具体不可用原因、信息栏摘要、机械日志、叙事／对白及文案包安全回退。不得保留与新事实冲突的旧文案，不得以内部ID、开发术语、泛化占位句或缺失正文代替完成；确实没有玩家可见影响时，必须在`RuleChangePackage.changedUiAndLogs`中写明`N/A＋理由`。
6. 按V0—V6补充或更新自动测试和UI证据；每例断言允许变化、必须不变状态以及本次文案表面是否齐全。
7. 日常修改只运行受影响分类的完整门禁：`npm.cmd run lint`与`npm.cmd test -- <分类>`；跨分类修改一次列出全部受影响分类，例如`npm.cmd test -- items content ui`。分类入口会自动合并所有包含所选区域的交叉测试，同一文件只执行一次。不得用单文件测试代替分类全量，也不得在普通开发批次默认运行全项目。只有发布、明确的跨全局重构或用户要求完整回归时运行`npm.cmd run test:all`，该命令包含生产构建和全部唯一归属文件。
8. 新增物品、装备、规则设定、环境、文案、界面或存档行为时，必须新增或更新自动测试。只覆盖一个区域的文件归入该主分类；承担两个以上区域或验证层边界的文件归入`cross`，并显式记录全部关联区域。新物品至少关联`items`，并按实际影响补`ui/content/persistence/restraints/world/core`；新设定至少关联其权威逻辑所属分类。不得复制测试到多个分类，也不得遗漏实际涉及的交叉区域。
9. 同步更新规则对照文档、`work/rule-verification-index.md`和协作看板。
10. 若项目包含 `.openai/hosting.json`，通过 Sites 工作流发布已验证版本。

网页表现采用批次集成节奏：规则内核、事务与自动测试可以按连续小阶段推进；完成一批有共同边界的主要底层能力并通过完整门禁后，再集中更新一次网页端入口、只读投影和对应UI。除非用户当轮明确要求修复界面，不要为了每个底层小阶段反复修改页面；集中更新也不得把尚未完成的底层能力伪装为可游玩功能。

## 后续新版 UI 集中重构契约

- 新版界面只在底层相关阶段成批稳定后集中接线；当前底层批次不得为展示中断，也不得在 React 复制规则。每批完成后运行专项、lint、build、全量测试及 localhost 浏览器验收。
- 整体采用电脑版优先的16:9情境式布局：左侧身体／拘束具树约20%，中央工作区由紧凑地图与对白并列并取得除右侧叙事／日志列外的全部主高度；右侧上部为叙事、右下为日志，左下为当前状态。地图底部的“移动／行动／当前地块／道具栏与魔法”四栏互斥显示并以低高度向上展开，四栏内部统一采用左右工作区而非上下长列表：当前地块左侧为高度层与单格特写、右侧为检查和环境操作；移动左侧为轮盘／进度／结束移动、右侧为移动条件；行动动作组分左右两列；道具栏与魔法左侧为魔法手、右侧为背包与拿取中。点击地图位置自动打开“当前地块”。当前地块继续显示场景自带、未固定和已安装固定内容及正式高度；拿取中显示手／嘴／脚趾操作来源；衣物不进入道具栏。缩放固定地图右上。底栏打开时点击栏外区域自动收回，栏内操作不得误关，各左右区可独立滚动。多回合移动／姿势行动显示分段进度。移动／转向共用一个可由中心“移／转”零回合切换的方向盘；行动栏的姿势卡继续使用双列。
- 整体视觉统一为“成人二次元魔法少女拘束游戏”，但普通界面禁止大面积粉红：以黑色皮革、枪灰金属和低饱和暖灰为主体，暗酒红只表达快感、危险与主角对白，哑金表达扣件、束带与重要边框，冷青只保留为魔法和必要信息高亮；高潮／强制状态才允许显著粉红。面板、装备卡、按钮、折叠栏与对白区使用日系游戏式半透明卡片，并加入克制的乳胶高光、皮革暗面、缝线／束带意象。不得退回纯开发工具式黑灰直角界面，也不要做成无主题的可爱星光界面；装饰不得降低规则数字、状态层级和地图信息的可读性。

## 子 Agent 协同机制

项目长期使用四个子 Agent 角色，详细配置位于 `.agents/`：

- 规则守门员：负责权威规则、冲突裁决、影响矩阵和实现契约，默认只读。
- 系统工程师：负责纯逻辑、装备事务、状态结算和行为测试。
- 地图与体验设计师：负责地图、视野、检查、环境、物品池及相关表现。
- 独立验证与发布员：负责只读回归、构建和发布前验收，不暗中修复被审查代码。

根 Agent 是唯一协调者，负责拆分任务、指定文件所有权、解决跨域冲突、集成 `page.tsx`、同步文档、提交与发布。当前任务和依赖记录在 `work/agent-board.md`。

协同规则：

1. 跨系统或规则不明确的任务先由规则守门员冻结契约，再开始实现。
2. 系统与地图任务只有在文件不重叠、依赖已满足时才并行。
3. `game-demo/app/page.tsx` 是集成热点，子 Agent 未获明确授权不得直接修改。
4. 实现 Agent 不验收自己的完成结论；关键重制必须交给独立验证员复核。
5. 子 Agent 必须按 `.agents/README.md` 的任务包与交接格式报告，禁止用模糊结论掩盖未完成项。
6. 同时最多运行三个子 Agent；有先后依赖的任务必须串行。

- 子 Agent 的职责、文件所有权或协作流程发生变化。
- 同类错误重复发生，且可以通过长期指令预防。
- 新系统形成不可破坏的架构约束。

一次性任务进度、临时阻塞和短期优先级只更新 `work/agent-board.md`。修改后必须以 UTF-8 复读检查；不要把聊天流水、部署令牌或临时路径写入本文件。

## 规则设计原则

- 随机结果必须可复现：生成函数应接受种子，不要把 `Math.random()` 深埋在规则模块中。
- 随机补装先过滤合法候选并取最高优先级，只在同优先级候选之间随机；随机域需混合种子，避免相邻种子长期产生相同结构。
- 玩家初始非快感拘束必须按规则书20.2A的“既有结构→具体拘束具模板→品质与允许材料”三层权重抽取。每层先删除非法与权重0项再按原始整数权重重归一化；合法部位数、内部变体数或材料候选数不得增加所属结构或模板的上层票数。缺失四警戒模板权重或`materialPoolId`的模板默认权重0，不得用完整候选等权兜底。
- 玩家正式初始生成必须保证低／中／高／极高警戒至少有1／2／3／4件不同拘束根带有效锁；同一复合根多把锁只计1件。未满足下限时先保留13.4既有安装优先级，再在当前最高优先级候选中只保留真实可锁完整候选；当前档没有合法锁位时不得降低安装优先级或伪造锁，而应照常安装并把保底顺延。抽中可锁根未随机出锁时，于真实可锁皮带扣／拉链扣上确定性补1把；额外锁仍按既有逐扣件概率。不得给绳结、软闭合、胶带、扎带、普通链接或手指／脚掌／脚趾普通拘束伪造锁，UI只按真实活动锁显示`🔒`。
- 玩家初始生成与NPC补装的安装优先级必须落实为13.4稳定档位`700/600/500/400/300/200/100/0`，依次对应未拘束手腕、未拘束嘴部／手指、未拘束其他身体部位、未拘束脚掌、未拘束脚趾、已拘束手腕、已拘束手指、其他已拘束部位；复合根取真实覆盖部位最高档，普通链接取两端最高档。不得再次只保留全为0的字段框架。
- `restraintCountUnits=2`的复合根只以一个模板候选进入权重池，剩余预算不足时预先排除，成功后原子消耗2单位；不得拆根、复制候选或用单位成本乘除权重。单腿套仍可在剩余1单位时只保留短版内部变体。结构、模板、品质、材料与模板内部随机使用互不推进的确定性子域。
- 玩家初始生成使用规则书20.1的有界重试：普通／快感名额最多16个候选，复合内部和特殊姿势最多8个候选，物品位置最多16个候选；超限记录shortfall并继续，不得无限循环或整局重开。特殊姿势类型、严重度与绳长只抽一次，局部候选失败不得借重试改抽类型或抬高出现率。初始床面特殊姿势额外检查至少一个符合模板移动轴、占格、承载、碰撞与落差的合法离床方向；该检查只淘汰冻结类型内部候选。
- 玩家初始流程已经冻结的非空特殊姿势类型，在普通拘束三层生成期间视为待安装兼容性保留；会占用其必要锚点、破坏姿态前置或形成明确互斥的普通候选必须预先排除。只有该冻结姿势自身8候选耗尽后才释放预留单位并按当时真实状态重建普通池，不得让普通生成间接压低特殊姿势实际概率。
- 当前阶段不运行真实可解性搜索，也不因缺少解除、工具、魔法或胜利路线重抽、拒绝安装或自动判负。生成与安装只验证本次候选的容量、层级、端点、互斥、组件、占格和模板局部物理合法性；初始床面离床方向属于局部占格／承载检查，不得扩展成路线搜索。无解时由玩家继续尝试或主动放弃。
- 力量、灵巧和智力的正常人物属性上限为10。智力就是原先决定魔法值上限的“魔力属性”，不是新增第四属性：公式为`魔法值上限=100＋智力×10`，同时参与堵嘴低／中言语阻碍判定；身体强化继续读取当前魔法值。既有代码／存档可保留内部`magic`字段兼容，但玩家界面不得同时显示魔力属性与智力两套数值。
- 当前人物创建只开放名字（默认“希凛”）、145—185cm整数身高、共用12点且各为1—10的力量／灵巧／智力、初始袜子与手套，以及确定性随机人物。默认身高160cm、属性4／4／4；脚长固定0.23H且不可调整。所选服装必须先于初始拘束安装，人物随机种子随后作为本局会话种子；不得提前开放敏感度、脚长或其他身体细节选项。标题页确认的名字是游玩界面人物署名和人物替代文字的唯一来源；对白、空对白卡、头像和地图人物不得继续显示通用署名“主角”，旧存档缺名时回退“希凛”。规则／教程中的角色类别和第二人称叙事正文不动态替换。
- 床的每个床面格必须提供独立`support.bed-surface＋object-top@0.80H`具体检查接口。无眼罩非躺姿的眼神范围包含人物当前格；手部横向候选包含床面格且手部检查通道可用时也可直接检查。床上坐姿可查当前格，床边站姿可查相邻格。床面与床底知识、检查次数、接口和物品必须继续按承载层隔离，检查床面不得泄露`support.bed-under`。
- 开局难度为简单／普通／困难，默认普通，只对实例真实耐久组件应用`0.80／1.00／1.20`：在材料、品质和安装词条之后向上取整并幂等保存基础最大耐久。主体、扣件、锁和独立性玩具耐久均适用；紧度、力量要求、滑脱阈值、候选资格和所有固定伤害不变。旧存档缺失难度时按普通解释。
- 标题页的基础非快感拘束数量允许按初始警戒档调整：低警戒`1—8`、中警戒`8—12`、高警戒`12—24／全部`，默认仍为`8／10／12`。“全部”是稳定`all`档，不是任意大整数或固定绳子方案：先按24单位档的正式结构权重随机生成普通件、头嘴、单手套、单腿套与拘束衣，再补全全部身体部位仍合法的叠层；普通首层从完整合法池随机，后续叠层在能保留当前可用暴露连接锚点的合法绳／皮带候选中继续随机。最后随机生成当前复合结构允许的全部普通连接；没有复合封闭时为上肢6段＋下肢7段，抽到拘束衣、长单手套或单腿套时不得为凑满13段绕过封闭和端点规则。相同种子必须复现相同组合，不同种子允许产生不同组合；真实容量、层级、互斥、封闭和端点限制不得绕过。普通数值只替换基础池请求单位数，性玩具、服装与特殊姿势仍按各自规则另行生成。难度与“现实模拟”在首页合并为一个视觉栏位；现实模拟三档显示名固定为“中杯／大杯／超大杯”，只重命名既有普通／硬核／超硬核机械设置。
- 硬核存档是独立开关：开启后，只要`restraints.roots`仍有活动、松垮、承接或尚未脱离的拘束根，就禁止写入任何栏位；服装与道具不计。读取、查看和删除不受限制，拒绝写入不得消耗回合、写事件或留下部分存档。
- 超硬核是硬核存档的上位互斥档：必须同时启用硬核限制，并完全禁用单步撤销；普通硬核仍允许撤销。旧存档缺少超硬核字段按关闭解释，超硬核开启但硬核关闭的存档组合必须拒绝。
- 局内撤销固定为一层、一次性会话快照，不提供重做。普通模式初始3次、每5个合格玩家回合恢复1次、上限10；硬核初始1次、每10回合恢复1次、上限5；超硬核固定0次。额度与进度属于`GameState`并随存档，帧只捕获成功玩家Command提交前完整`GameState＋eventHistory`且不进存档。只有行动前已有额度才发布帧；成功撤销恢复行动前玩法状态，但额度固定为行动前减1、进度回到行动前，防止刷次数。撤销采用SL语义：保留撤销请求前全部随机域游标和下一事件序号，状态版本在撤销前版本上加1；重做同一行动使用下一抽取并生成新事件ID，不固定复现被撤结果。失败／过期／回滚保留旧帧，成功但行动前0次时清旧帧；0回合行动不推进恢复，正式玩家回合逐次推进，强制回合与独立NPC步不推进并清帧。撤销不写事件、不推进回合，也不额外抽随机。
- 当前魔法值参与力量与灵巧乘区；临时魔法值超过上限时，倍率允许继续提高。
- 环境修正属于地图或地块数据，不应硬编码成所有沙盒共用的固定奖励。
- 场景高度是不可随人物缩放的场景事实。地面、家具承载面、家具净空、环境接口区间和固定构件高度只能读取当前`SceneDefinition`或按场景种子一次生成的固定值；人物身高、身体比例、姿势、半蹲、抬腿和压腿只改变人物点位与操作扫掠，绝不能回写或迁就性调整场景高度。墙缝高度只在世界生成时确定一次，物品安装后的`installedHeightH`保持固定。
- 水平承载面接触的`0H`是当前承载面的相对高度：站立脚踝／脚掌／脚趾，坐姿全腿与手腕／手掌／手指的点位区间下限可到当前承载面；坐在床上只到床面，不穿透到世界地面。普通卧姿保留中心厚度高度，但由四态身体侧决定朝下接触面：仰卧背面、俯卧正面、左侧卧左侧、右侧卧右侧。环境候选必须同时验证真实点位、格、承载通道、高度与身体侧。
- 便携物品的正式水平承载层必须逐格唯一寻址：裸地／走廊为`inner-floor@0H`，床面为`support.bed-surface＋object-top@0.80H`，床底地面为`support.bed-under＋inner-floor@0H`，桌面为`support.table-surface＋object-top@1.00H`，桌底地面为`support.table-under＋inner-floor@0H`。桌面只承载物品，不开放角色占据；`object-bottom`表示家具下表面，不得作为床底或桌底的0H落物地面。
- 失败保留已造成的解除进度；大失败可以倒退。耐久不会随普通时间自动恢复，只有规则明确声明的事件、外力或正式`magicSelfRepair`词条可以恢复对应主体。
- 数值平衡以“单件通常可尝试、中档以上同层复数常把常规状态推过自身解除门槛、环境／道具可按单件打开缺口”为目标；保留`difficultyCoefficient=0.50`和规则书7.4A的`3/5/7`要求锚点。环境的优势来自单件隔离、越过末端、扣件路线和固定进展，不得改成全局加骰或恢复同层聚合。
- 玩家可以不清空拘束而完成场景目标。除解除胜利与规则明示的层级／结构计算外，拘束总件数、总耐久和全身总要求不得成为检查、移动、取物、施法、开门或出口行动的通用减值／硬禁用；这些行动只读取实际操作链的整合后角色效果、姿势、触及、操作点和用途资格。
- 双腿自由的普通站立每回合5格移动允许前进、保持面向后退，并在活动移动事务中0回合左右转向；转向保留已用步数，前后位移都各计1格。大腿／小腿部分并拢或足端并拢的3／2／1格事务仍只允许锁定方向前进或主动结束，不得仅在UI伪造后退或转向。
- 移动框中的向前、向后、左转和右转若不可用，必须由正式固定点状态、效果和地图碰撞投影出该方向唯一、精确且通俗的原因并常驻显示；玩家正文要代入主角行为，以第二人称说明“你怎样移动、身体会碰到什么、动作为什么做不完”，不得直接显示承载面、净空、占格等规则术语，也不得使用“墙或家具”“当前姿势或空间”等多选猜测句。React只能显示原因，不得根据按钮位置、中文标签或内部ID猜测。不可用方向不生成伪造失败候选，也不能只依赖鼠标悬停提示。
- 前进／后退按钮的位置与箭头必须对应实际地图方向，而不是固定表示相对身体的上下：面北／东／南／西时前进分别位于上／右／下／左，后退位于相反方向。左右转90°必须作为方向十字外的独立按钮；React只能读取稳定朝向做纯布局映射，不得自行计算目标格或改写移动候选。
- `Buff／Debuff`只指改变玩家行动能力的角色效果贡献，正负极性只用于显示。姿势与触及几何、结构资格、主体／扣件物理状态、资源、知识、事件和纯表现不得伪装成角色Buff／Debuff。
- 角色效果必须经过`effectContributions[] → resolvedActorEffects → ActionEffectView`三层。原始贡献、整合输出、`DurationSpec`与目标修正必须使用规则书3.2正式字段；来源不得按显示名称或装备总数合并。同一`sourceRef＋effectId＋scopeKey`先去重，同一操作节点只取最强干扰，不同必要节点才累计，硬禁用优先于普通数值修正。
- 目标数值修正留在`targetModifierContributions[]`，只存在于单次合法行动候选的效果留在`candidateEffects[]`；两者都不得进入常驻角色状态页。由多个事实推出的“上半身自由”“稳定抓握”等权限必须输出为只读`derivedPrivileges`，禁止进入原始／整合效果池或作为持久来源字段保存。
- `operatorCapability.*`只表示硬能力完全不可用；仍能继续操作的分档干扰统一进入`limbControl.*`。无法移动只使用`movement.blocked`，不得同时写入姿势转换或其他同义通道；特殊姿势的移动轴、速度、转向成本与占格始终保存在`postureState`。
- 状态固定点必须先稳定结构、物理事实与姿势，再合并角色效果和目标修正，最后派生权限、移动与触及。固定点必须幂等，不得发出事件、重放伤害或递减`actionBound/publicTurns`时效。
- 玩家普通骰统一使用`1d20+actionValue+namedFlatBonuses-challengeValue`及连续区间`≤0 / (0,10) / [10,20) / ≥20`；自然1/20只在真正投骰后生效，不能穿透结构禁用。姿势、支点、链接与结构不得提供泛化倍率，只有规则明示的具名平坦值可以进入判定。
- 玩家自身力量挣扎与普通灵巧滑脱先检查“方法与真实目标是否存在”：目标仍穿戴并物理占位、可解析唯一现存`physicalActionTargetId`和真实主体／组件、生命周期仍允许该方法、模板明确开放该精确目标的方法且提交版本未过期；缺任一项才是`blocked`、零消耗。通过后，数值、端点、层级、外层、锁具、链接、紧度阈值、姿势或自身触及不足均为可点击`guaranteedFailure`：消耗1公开回合、0骰、0损伤，并按唯一目标触发一次适用失败事件与词条。环境、道具、魔法、扣件处理和快速解除不继承本例外。
- 力量与灵巧是角色行动属性；装备的`currentStrengthReq`是力量挣扎挑战值，`currentTightnessReq`是普通灵巧滑脱挑战值。当前普通材料不得长期保存旧`dexterityReq`；旧字段只作迁移输入。未来真正不以紧度表达的专项模板才可声明`specialDexterityRequirement`与唯一`slipChallengeSource`，同一行动不得同时读取专项灵巧要求和当前紧度。
- 玩家可见的自身判定必须展示骰子、基础属性、魔法倍率、临时值、快感倍率、具名加成、要求和最终分数；环境／道具行动展示基础值、控制属性、操作修正、有效值、目标要求、固定效果和结构资格，不伪造骰子。
- 所有新增规则都要检查：堆叠、内外层、端点、锁具、链接、加固、姿势、触及、魔法、快感和警戒度之间的交互。
- 警戒自然衰减保存独立`alertDecayProgress=0|1`：每提交2个合格玩家回合，回合末警戒`-1`，但按当前警戒层永远不得低于`0／30／60／90`；一旦达到30、60或90，自然衰减不能再退回更低层。到达本层下限时仍消费进度并归0，但不写无变化事件。触发快感100的普通行动回合计数，但随后不可控的快感100强制特殊回合不计；NPC主导流程、隐藏步骤、零消耗失败、UI／预览、测试控制台和胜利后状态均不计。声音先提高警戒并记录本回合向上阈值峰值，再按提高后的警戒层结算衰减；下降不撤销已触发的20/50/80事件。
- 20／50／80三个警戒阈值事件在同一沙盒各自只能触发一次；30／60／90只是自然衰减下限，不属于这一组事件。三个阈值分别使用唯一消费身份并保存于`triggeredAlertThresholds`；警戒回落后再上升、普通回合与快感100强制回合切换、NPC步骤、固定点、页面重开和读档都不得重置或重复触发。测试控制台改值不产生也不清除事件，只有新建沙盒重置。未来新增警戒特殊事件必须先有稳定身份与持久消费集合，禁止只监听当前警戒而重复执行。

## 拘束具系统不可破坏的约束

- 双腿折叠并拢固定是一件特殊躯体固定拘束，使用自身独占的特殊固定通道；它不是由两件既有腿部拘束加上一根隐藏链接绳拼成的加固包。其大腿主体是真实物理行动目标，开放模板规定的挣扎判定；姿势维持、移动或滚转造成的自动挣扎也作用于该主体。不得生成、显示、保存或结算所谓“隐藏内部链接”。

- 服装是提供角色效果贡献或目标修正的独立`clothing`附加装备，使用所有拘束具之下的`clothingBaseLayer`；该底层只用于穿脱资格和效果覆盖，不产生其他层级互动。服装不占拘束容量、不参加同层聚合、链接锚定、快速解除、拘束魔法或“解除全部拘束”胜利计数。穿上／脱下都要求全部覆盖部位不存在任何仍物理占位的拘束，资格通过后固定成功并消耗1公开回合；不得从已有拘束下方补穿服装。

## 姿势与移动

- 基础姿势只有站立、坐下、躺下，并且只能按顺序互相切换。
- 普通躺姿占据沿朝向排列的两个格子；特殊躺姿占据一个格子，除非最新规则另有声明。
- 移动需要多回合时，每次按钮点击仍正常推进一回合；达到要求次数时才改变坐标。
- 普通站立移动使用“每回合格数”预算：双腿自由 5 格、大腿并拢 3 格、小腿并拢 2 格、脚踝／脚掌／脚趾并拢 1 格跳跃；每次合法点击立即移动一格，达到上限或主动结束才结算回合。不要与特殊姿势的“多回合移动一格”进度混用。
- 普通坐姿及仅有大腿／小腿等局部并拢、尚未形成完整双腿并拢时可直接固定成功站起，不要求支点。只有摔倒恢复或已派生完整双腿并拢时才要求当前真实手部可用，且墙、关闭牢门、床或桌必须正好位于角色背后一格；前方、左右和九宫格其他格均不算。支点不提供数值倍率；只有“摔倒来源＋完整双腿并拢”投力量骰，难度仍为`6+下肢严重度0/1/2/3`。
- 多回合移动进度必须绑定方向与目标格；中途改变方向或目标时从 1/总需求重新累计，不能继承上一方向的进度。
- 失败且没有实际移动的空间检查不消耗回合，也不结算移动附带效果。
- 实际位移的结算顺序固定为：更新目标坐标候选 → 跳跃或特殊姿势自动挣脱 → 统一重算装备与特殊姿势 → 仍为站立时判定跳跃稳定 → 解析床铺承接或地面落点 → 结算固定式快感增量 → 检查快感 100。不得先摔倒再结算自动挣脱。
- 跳跃自动解除依次扫描大腿根、大腿中、膝上、膝下、小腿中、脚踝的合法最外层目标，并按`physicalActionTargetId`去重；易滑区加成+3、普通区+1。跳跃落地稳定使用灵巧，难度为`3+眼罩0/1/2/3+足端0/1/2+明确不稳表面0/2`，不读快感，失败不得撤销位移。
- 特殊姿势必须实际控制可移动方向、每格回合数、转向回合数、占格、触及范围及站起/坐起权限。
- 站立、坐下及其他单格姿势的原地转向只检查当前占格，不得被相邻墙体或墙角误判阻止；普通躺姿以头部格为轴验证第二占格，优先改用另一侧 90° 转向，必要时允许合法的双倍耗时 180° 调头。
- 并腿驷马和腿部折叠加固是当前仅有的两种有效特殊姿势来源，生成时检查互斥条件。分腿驷马与躯干—腿部特殊链接已分别移至 `work/archive/deferred-split-hogtie.md`、`work/archive/deferred-torso-leg-link.md`，不得进入当前生成池或派生状态。
- 并腿驷马必须叠加在有效的 `双臂吊起交叉` 上。`双臂身后平行交叠`当前只保留未来数据枚举，在独立点位、自然活动包络与环境接触表冻结前，生成、手动安装、脚本安装及姿势前置验证都必须拒绝该值；旧数据读取该姿态时降级为`双臂身后`并记录迁移冲突。运行中吊起交叉失效时，驷马链接按失效组件清理并撤销特殊姿势贡献。
- 特殊躺姿的触碰检查固定为占据的单格，可分别建立条件手部与条件足部候选，但两者都不能扩到相邻格或互相替代。所有坐姿的地图手部检查范围统一为自身占据格，不设上半身自由例外。近距视野与触碰检查是不同权限，不得因十字视野扩大检查范围。

## 地图、视野与检查

- 物理高度统一使用 `H`，且 `1H=1m`；默认角色身高`S=1.60H`、脚长`F=0.23H`，默认比例`F/S=0.14375`。角色模板可以覆盖`S/F`，但所有脚踝—脚掌—脚趾派生点位必须随之重算；旧`F=0.34H`数据失效。`H0/H1/H2+`只代表场景详情分组，不是物理长度单位。高度仍按手部、足部、嘴部检查通道和姿势模板处理，不为每件单部位拘束建立人体比例坐标。
- 横向触及一律读取规则书23.7的姿势候选格，不计算臂长、腿长、脚长、格内偏移、平面骨段投影或欧氏距离。连续数值只用于纵向高度、承载高度、局部扫掠与净空；高度重合不能让候选格外的目标变得可达。
- 普通站立与半蹲的足部候选都固定为自身格。普通坐姿手部强制为自身格；坐姿足部固定为自身格、身前1格、正左1格、正右1格，不包含身后，也不随腿部拘束增减。普通躺姿手部为上半身格、足部为下半身格及其左右；单格特殊姿势手足候选都不超出自身格。
- 半蹲、抬腿和压腿是临时纵向调整，不消耗公开回合，但每次执行都独立、可反复结算规则规定的固定式快感；目标行动后按各自规则清除。抬腿可以使用骨段长度计算纵向扫掠，但不得把水平分量用于格子资格。
- 半蹲的眼、嘴、颈与相关上半身点必须读取同一个`resolvedCrouchDrop∈[0,0.50H]`；拘束或净空只允许部分下移时，嘴高只能降低同一部分值。旧“半蹲嘴部不下降”规则失效。
- 普通坐姿中，嘴部自由、未夹持物品且头颈允许前俯／侧转时，玩家自身力量挣扎或普通灵巧滑脱会默认检查`seatedMouthAssist +2`。目标严格限大腿根、大腿中、膝上合法最外层／公开组件并须与坐姿嘴部扫掠重合；膝下及更低目标即使高度重合也禁止。它是`candidateEffects[]`具名平坦加成，不穿透锁、链接、紧度阈值或现行可点击必败，也不与同一操作节点的其他辅助累加。
- 坐姿嘴部扫掠冻结为`[seatSupportHeight+0.10S, seatSupportHeight+0.55S]`；站姿嘴部放置扫掠为`[supportHeight+0.86S, supportHeight+0.92S]`，半蹲整体减去真实`resolvedCrouchDrop`。这些都是行动内纵向区间，不是横向距离或常驻高度通道。

- 堵嘴但头部可动时，当前所有可移动小型物品必须设置`blockedMouthNudge=true`：在嘴部候选格、点位高度、遮挡、揭示状态和随身栏容量均合法时，角色可用1公开回合把物品直接拨入随身栏。该流程不建立`heldBy=mouth`，也不授予叼持、安置、开锁、切割、钩拉或任何装备进展；中型和大型物品不能这样拨取。模板只有在物品被锚定、尺寸异常或场景明确禁止推动时才能显式设为`false`。
- 当前物品分类仅开放`keyTool/edgeTool/hookTool/transformable`，空易拉罐与台灯暂不建立模板或进入生成池。分类只用于归档、显示与生成池筛选，不能作为操作权限来源；取得某物品也不代表能使用它，拿取与每个用途分别读取自己的操作组、控制要求、目标兼容与回合/次数成本。
- 道具与环境的能力档位表示可处理的最高要求并一律向下兼容：档3覆盖档1/2/3，档2覆盖档1/2，档1只覆盖档1。精准滑脱向下包含普通滑脱，精准切割向下包含普通切割，但滑脱族与切割族不得跨族替代；向下兼容不改变模板明示的固定值或损耗数值。松垮载荷只存在原贴合档2/3：`maxSlackTier=3`可处理二者，`=2`只处理档2；档1滑脱成功必须直接离身，禁止生成松垮实例、承接引用或钩拉目标。
- 环境／道具滑脱只提供用途明示的`baseSlipValue`，不投骰；动作声明`controlAttribute=strength|dexterity|none`，按角色当前属性、魔法、快感与实际操作链得到[-2,+2]操作修正，再比较`effectiveSlipValue`与所选单件的`resolvedSlipRequirement`。它不削减紧度或累计进展，也不应用同层聚合；紧度阈值及锁具、链接、外层、触及与模板限制仍先判。
- 环境可以越过普通肢体末端扫描和默认目标清单选择任意合法暴露、接口兼容目标。同层复数普通单件在环境行动中独立计算：目标允许力量挣扎时可按该实例自身要求投完整普通力量骰；模板禁用力量挣扎时不得投骰，只能在`effectiveOperationValue>=operationRequirement`后结算用途固定损耗，且不得附带普通挣扎伤害或0.50倍扣件损耗。同次行动不得叠加力量骰和固定效果。
- 眼罩和带式口球都保留不投1d20的特殊滑脱，以环境／道具`effectiveSlipValue`逐件比较解析后的自身要求，并先检查紧度阈值及结构资格。角色状态只能通过外部操作修正影响有效值，不能改接普通灵巧滑脱骰。
- 外部操作要求低／中／高池为6/8/10，基础操作值池为6/8/10，基础滑脱值池为2/3/4，锋利系基础操作值固定12。能力档只作向下兼容门槛；力量、灵巧、魔法与快感可以改变操作是否有效，但成功后的`bodyDamage/fastenerDamage/lockDamage`始终使用模板固定值，不得缩放。
- 手持／随身道具与安装后派生接口共用统一`ActionCandidate→ActionTransaction`、唯一目标和单件独立算法。安装只替代持续握持并改变位置、高度、驱动点与控制方式，不改变基础效果值、紧度阈值、材料兼容或次数；固定墙缝工具继续不模拟道具方向或工作轴。
- 锋利系道具使用`baseOperationValue=12`，最低操作修正-2时仍能通过当前最高10的兼容要求；成功后的固定损耗不被放大。直接与安装状态保持同一基础值和伤害；锋利仍不绕过材料、扣件类型、外层、暴露、锁具或操作权限。
- 物品实例分开保存`locationState=surface|held|inventory|installed|consumed`和`useState=usable|spent`；小型携带成本1、中型2、大型不可进入随身栏。有限次数归零时只把`useState`改为`spent`并保留位置，只有明确`consumedOnUse/transformOnUse`才进入终止位置，安装接口不得复制物品次数。
- 环境与道具损耗必须同时匹配唯一目标、材料标签和扣件类型；普通切割不能主动处理扣件，精准工具也只能处理自身`compatibleFastenerTypes[]`，锁具仍是独立目标。主体／扣件处理还必须满足有效操作值比较；无效或数值不足不耗回合／次数，通过后才按用途结算固定损耗与成本。
- 朝下固定环境物只允许小型或中型实例。坐姿先按统一格子表确认足部候选，再只比较脚趾、脚掌、脚踝的纵向高度；普通躺姿的腿部目标在高度覆盖成立后，小型只作用脚掌/脚趾拘束，中型额外开放脚踝拘束。眼罩、口球/堵嘴须按自身相对高度、占格、暴露、扣件类型与材料判定，固定精准点不检查工具方向或身体侧；链接按上下两端任一合格锚定拘束继承一次环境资格；特殊姿势无默认豁免，须通过自身点位模板。
- 并腿驷马使用0—1归一化绳长而非米数。大小腿夹角从 `L=1` 的45°连续收拢至 `L=0.2` 的30°；进入极限档后保持30°，大腿再从0°连续上抬至 `L=0` 的30°。严重度档位与连续姿态几何分开计算，旧 `max(0.3,0.5×L)` 脚部高度公式不得继续使用。
- 吊起交叉站姿及其叠加特殊姿势的点位采用规则书12.3的局部相对高度表：承载面为0、默认身高1.60H、表值为默认点位高度除以身高。每个点位还按部位组取得自然活动半径 `Δr`；环境先检查 `[r₀-Δr,r₀+Δr]`，再检查空间与身体侧。该表不得扩展成所有普通姿势的全量人体坐标，且不包含半蹲、抬腿、压腿等额外动作。
- 普通手部自然纵向活动使用同姿势腰部 `W` 与大腿根 `G`：手腕下限为 `G+0.45(W-G)`、手掌为 `G+0.20(W-G)`、手指为 `G`，三者上限均为 `W`。吊起交叉时手腕 `Δr=0`，手掌/手指只保留模板少量活动。多个躯干固定只读取最末端一档（手腕＞小臂＞大臂），不得叠乘；手腕固定令手腕范围为0，并把手掌/手指切换为对应姿势吊起交叉的少量活动模板。
- 敏感部位机械身份固定使用`focus.slot.1/.2/.3/.4.1—4.4`，玩家可见名称依次为乳头、小穴、后庭、马眼、龟头、冠沟、柱身。显示名称不得作为状态枚举、随机键或事务分支；旧“敏感部位1”等只作迁移别名。乳头的纵向参考是当前姿势的大臂中间点位，其余六个敏感部位继续使用普通手腕参考。
- 平面、墙面、床面、床底、桌面和桌底使用各自的交互模板，不要仅靠显示名称区分。
- 床面、床底、桌面和桌底使用共享但会耗尽的确定性物品池；固定隐藏点与普通随机地面点不得混入同一概率池。
- 物品模板抽取、单实例位置、墙面工具缝位置和墙缝高度分别使用`itemSpawn/itemPlacement/wallFixturePlacement/wallFixtureHeight`随机域；物品位置按实例独立子域确定性洗牌并无放回尝试，墙缝高度按`0.05H×randInt(1,49)`生成。同一版本和种子必须复现，某件物品位置失败、行动判定与叙事随机不得改变其他地图生成结果。

- 堵嘴且头部可动时，每个当前可移动小型物品都能按合法候选格拨入随身栏，但不会产生嘴部持有或物品用途资格；中型物品必须拒绝。
- 长版单腿套本身不得自动派生膝关节姿势硬禁。

- `隐藏扣环`沿用稳定词条ID `hiddenFinish`。它必须指向已有真实主扣件，检查与详情仍可显示，但扣件固定`exposed=false`且任何直接处理候选均不可用；不再依赖覆盖组件，也不阻止主体方法或既有受力传导。
- `感应收束`在每次已提交的真实位移后触发一次；统一以提交前后角色主占格／承载锚点是否改变判定。分段进度、原地转向、失败／过期／回滚移动及主锚点不变的姿势占格变化不得触发。
